# 认知星图 3.0 发布清单

3.0 是本地单用户学习工具的功能定版。范围覆盖资料与题库整理、搜索、练习与自测、错题与到期复习、学习计划、可选 AI 辅助，以及本地备份、恢复和文件分享。以后以正确性、安全、兼容性、性能和易用性维护为主。

多人教学和协作、社区和题库市场、通用 AI 助手属于范围外。自动同步、内置 OCR、语义搜索和其他候选能力留在备忘。日常学习、资料阅读和复盘保持可离线使用。软件与领域题库包独立交付。

当前软件版本为 `2.0`。后台任务、批量传输、AI 推荐覆盖、真实 PDF 全文检索及教材出题已实现，部分流程已有专项报告。以下复验都针对最终 3.0 候选提交或由其生成的交付包。已有功能通过对应验收即可勾选。

## 一、功能收口

本节勾选表示当前源码已完成相应闭环。正式 3.0 候选包仍统一执行第三节的最终验收，设备升级另按第二节核对。

- [x] **首次使用。** 空库引导和新目录接续旧库的指引已实现。网页和雷电专用 QA 包通过首练流程，Windows 独立服务通过裸 SQLite 停机恢复。正式候选包继续复验各端入口和升级路径。
- [x] **题库和资料。** 2026-11-10 通过分类映射、编辑草稿与修订、审核、质量反馈、近似题核对、搜索和返回定位。历史 2.0 代表性领域包转换后通过导入与重复题复用。Markdown／文字 PDF 通过原文检索高亮、双向关联和旧版本引用。扫描版和超限文件提供可操作的后续路径。
- [x] **学习闭环。** 2026-11-10 通过单题、随机抽题、题集浏览、普通练习、考试和专注复习的专项。覆盖客观判分、主观评价、组合小题、双向词卡，确认退出停表、草稿恢复、考试锁定、并发与到期交卷只记一次，作答期间隐藏笔记和历史提示。
- [x] **记录与复习。** 2026-11-10 使用同一实际题库题集串起作答、错题／收藏、到期复习、FSRS 反馈、学习计划和周报。专项核对历史清理、指定范围重置、单次统计和幂等重试，编辑原题后历史答卷仍使用原快照。证据见[学习闭环复验](./验收记录.md#2026-11-10-学习闭环复验)。
- [x] **AI 全链路。** 2026-11-10 使用隔离数据和现有 DeepSeek 完成 9 组代表场景、12 次真实请求，核对推荐题量及必达覆盖、教材关联、待审核入库、题集判题标准、评价应用及用量记录。210 项可控契约测试及 8 个浏览器专项通过，覆盖无效输出、供应商失败、取消、重试和分块续做。真实模型属于抽测，详见[本轮 AI 与传输复验](./验收记录.md#2026-11-10-ai后台任务与导入导出复验)。
- [x] **后台任务与导出。** 2026-11-10 通过后台任务、SQLite 迁移与数据包的 3 个浏览器专项，共 19 项检查；最终修复后的构建又通过后台全流程 8 项。覆盖切页继续、通知、结果与草稿恢复、取消重试、待审核导入、ZIP／SQLite 下载。后端专项验证重启中断、分块续做和幂等；另通过 PDF／Markdown／ZIP 分享、Android WASM 传输运行时及万题磁盘库往返。关闭服务后的重试和本地 PDF 排版边界按现有说明保留。具体范围见[本轮 AI 与传输复验](./验收记录.md#2026-11-10-ai后台任务与导入导出复验)。
- [ ] **日常使用缺陷。** 以验收中复现的问题为准，优先修复阻止开始练习、继续草稿、交卷、复盘或恢复的交互。保留现有入口组织，优先处理手机遮挡、文件选择、键盘和失败后无法继续。

## 二、数据安全、兼容和容量

- [ ] **用 2.0 数据做实际升级。** 从旧正式版本和现用学习库的备份副本分别验证 Windows、Web 与 Android 升级路径。抽查题目、题集快照、作答、错题、笔记、复习状态、计划、草稿、附件及原文引用。冷开升级后再重启验证数据仍在。
- [ ] **跨端迁移和恢复。** 用整体及指定领域 SQLite 迁移样本验证读取、配置保留和引用完整性，确认迁移副本清除 AI 密钥及本地任务回执。校验损坏、超限或不兼容的文件，预览后再替换，失败保留原库。验证最近的恢复前副本可导出并能实际恢复。演练停服务后用旧程序和升级前备份回滚。Windows 便携版至少有直接导出 `.sqlite` 后停机替换的恢复步骤，Android 走应用内恢复。
- [ ] **Android 真机。** 使用由候选提交生成、拟发布的正式签名 APK，验证全新安装和从旧正式包覆盖安装。用实际规模的隔离库做离线练习、文件导入、保存、进后台再返回、系统结束进程、重启、考试到期、PDF 阅读与系统分享；复测已有 SQLite 恢复。记录设备、系统版本、库体积及实测限制。
- [ ] **性能与空间。** 复跑已有规模专项，区分日常启动、搜索、打开题集和保存，与首次 PDF 索引、大包查重或迁移。记录耗时、峰值内存及文件占用，检查后台任务缓存、取消后的临时文件和 Android 恢复副本累积。仅在复现卡死、无法保存、空间耗尽或明显回退时做针对性修复。
- [ ] **公开题库包。** 决定复用已验证的内容版本还是重新导出。需要新包时，在版本确定后单独运行 `npm run content:domains`，用一致性数据副本和独立输出目录。对本次上传的各包检查清单、校验和、依赖与来源许可，并在空库抽查首次导入、重复导入及跨领域引用。驾驶题和图片等再分发权限未确认的内容从公开附件中排除。题库包继续独立发布，私有教材、作答、笔记和配置留在个人库中。

## 三、候选版本和发布验收

- [ ] **确定唯一候选提交。** 核对当前 2.0 之后的提交和工作区变更，收齐后台任务、PDF、覆盖要求等代码、测试和说明。同步 `package.json`、`package-lock.json` 和 `3.0` 版本说明。从干净检出安装锁定依赖，并以候选提交生成最终交付物。在验收记录中写明候选 Git 提交号，确保标签和附件来自同一份源码。
- [ ] **最终自动化。** 在候选提交执行 `npm run check`、`npm test`、Web 与移动资源构建以及核心浏览器专项。至少覆盖组题、练习／考试、复习、资料检索、AI 与后台任务、ZIP 和 SQLite 迁移。要求零失败，逐项说明按可选数据或环境跳过的检查。上一轮全量有两项 QA 清单断言失败，修复后已通过专项复跑，仍需最终候选完整通过一次。
- [ ] **生成并验证正式包。** 在 Windows 发布环境运行 `npm run release -- all --version 3.0`，正式打包保留完整检查。产物应包括 Web 运行 ZIP、Windows 便携 ZIP、正式签名 APK 和源码 ZIP。用 `npm run windows:smoke -- <解压后的EXE>` 在仓库外验收桌面端，用 `npm run release:smoke -- --install` 验收 Web 包的生产依赖安装、启动、重启和持久化。Docker 如作为已支持交付，须实际构建、启动并验证卷持久化。只提供构建命令时使用 `--docker-command-only`，并在发布说明标明实际验证状态。
- [ ] **核对版本、签名与发布边界。** APK 保持正式应用 ID 与原正式证书，`3.0` 的 `versionCode` 应为 `30000`。核对各产物版本、清单、SHA256 和签名报告。检查软件包仅带基础配置与必要运行资源，空题库、AI 默认关闭，默认服务仅本机可访问。源码、运行包和报告均排除工作库、密钥、签名私钥、个人资料和测试临时件。
- [ ] **同步发布文档。** 完成 `3.0` 更新说明、安装与首次导入、备份／升级／回滚、已验证平台和已知限制。同步 README、应用内手册、部署说明、接口变更和验收记录中的相关段落。修正 GitHub 发布说明模板中已下线的独立「配置迁移」入口，改为当前的 SQLite 整体或领域迁移。统一手册中草稿保存与后台任务离页的说明。明确旧规划的候选功能归入备忘，后续版本按维护修复发布。
- [ ] **发布 GitHub Release。** 确认最终验收通过后，推送已验收的候选提交，创建 `v3.0` 标签与发布草稿。从本次 `release-report.json` 的 `uploadDirectory` 核对并上传软件附件、发布清单和校验和，另附选择发布的领域包与内容校验和。预览下载和升级说明，发布后从 Release 页面下载代表性附件复核 SHA256，并保存对应的构建与验收报告。

## 放行条件

按前三节确认必验项全部通过，并在发布说明记录未交付的条件项。数据损坏、丢学习进度、确定性判分错误、启动或恢复失败、正式包无法覆盖升级、安全边界失效均阻断发布。轻微体验问题登记到后续维护。
