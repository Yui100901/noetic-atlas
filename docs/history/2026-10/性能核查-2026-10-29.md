# 启动、查询与使用体验核查

本轮针对启动校验、统一搜索、资料目录和筛选交互定位瓶颈。测试使用合成内存库或临时文件库，没有打开实际题库进行测试，也没有改写学习数据或私人配置。测试期间不重启现有工作服务。

## 已修复的问题

| 场景 | 原因 | 改动 |
| --- | --- | --- |
| 已有数据库启动慢 | 无需旧标签迁移时仍载入题目和资料正文；逐题引用检查反复查询分类标签 | 先检查是否存在旧标签；只读取引用数组，一次载入分类标签后校验；每次启动仍核对全部引用与附件 |
| 历史迁移占用启动时间 | 枚举全部题集快照及组题草稿再找旧字段 | 数据库先定位真正包含旧字段的记录；空库判断只取一条标识 |
| 宽泛统一搜索开销高 | 全部匹配携带展示数据和排名，分类统计又把每页记录重复返回 | 匹配集保留标识与类型，按选定类型计算排名分页；统计和结果分别返回，每页数据只解码一次 |
| 教材目录传输过大 | 分页也携带整篇Markdown正文 | 新增 `GET /api/documents/page`，只返回当前页卡片元数据及110字符摘要；正文按详情请求 |
| 资料正文搜索仍慢 | 重复提取完整JSON、拼接字段并转换大小写 | 增加可重建资料投影；保留原始Markdown子串匹配及Unicode大小写语义，编辑后只刷新变化记录 |
| 切换筛选时出现重复请求和旧结果 | 页码重置与筛选更新分开，所有条件一起防抖 | 仅关键词防抖，等待期间不发中间请求；离散筛选与页码一起更新；按当前URL接收结果 |
| 分页、返回和顶部搜索不顺手 | 越界页缺少返回入口，新的顶部搜索重置结果类型和排序 | 超出范围回有效末页，零结果保留分页；重新搜索保留类型、排序、未发布开关与每页数量 |
| 初始推荐刷新重复 | 两处初始化触发同一请求，开发模式还会试运行Effect | 保留单一初始化，微任务检查卸载；反馈摘要同样避免已取消的开发模式请求 |

## 测量结果

以下均为本机合成基准。HTTP数据为进程内请求完成耗时，不能直接等同于实际网络、设备或Android真机速度。各大型基准分别执行，未与构建或全量测试并行。首次索引构建单独记录，不混入稳定查询。

### 3万题文件库启动

| 指标 | 改造前 | 改造后 |
| --- | ---: | ---: |
| 干净数据库重开两次 | 4.17 / 4.09秒 | 1.50 / 1.51秒 |
| 分类标签引用校验 | 2.01–2.08秒 | 253–258毫秒 |
| 无旧标签时的迁移检查 | 828–863毫秒 | 约0.11–0.12毫秒 |
| 每次启动逐引用查询 | 60,000次 | 0次 |
| 每次启动读取全部题干 | 3遍 | 1遍，保留附件验证 |

首次创建全部派生索引约17.49→14.83秒，属于新库/待构建投影的成本。原有干净库仍验证引用与附件，未通过跳过校验实现提速。此项主要优化发生在已有数据的重复启动。改造后数值在所有代码与构建、浏览器回归结束后单独重新测量。

| 宽泛搜索，全部类型 | 145.79ms | 77.94ms |
| 宽泛搜索，限定题目类型 | 146.27ms | 77.44ms |
| 第200页 | 218.60ms | 106.81ms |
| 中文概念 | 85.16ms | 65.34ms |
| 英文多词同时匹配 | 86.84ms | 65.07ms |
| 日文检索 | 85.89ms | 65.17ms |

20条展示记录从重复读取140条降为20条。精确ID子串搜索约58ms，基本没有变化；首次统一搜索投影构建约5.58秒另计。中英日、全角半角、标点字面量、排名、类型计数和参考答案不直接展示等语义保持。

### 1,000本合成教材

每本正文138,037字节，约138MB原文。初步仅缩小响应时，卡片页仍需84.25ms，正文搜索仍需2049.57ms；这促成了本轮资料投影。

最终稳定20条卡片页中位3.90ms，正文检索316.36ms。完整正文分页响应2,767,647字节，卡片页12,607字节，传输减少99.544%。单独构建资料投影约2.30秒，之后只更新变化项。资料内容类型列表也读取精简投影。

投影另有独立版本号。旧库增加资料投影时只排队资料，不会重建所有题目/题集索引；源实体、附件、审核状态和时间戳是权威数据，索引可丢弃重建。旧的资料完整接口仍保留给详情、导出等既有调用。

## 数据库和边界

业务查询继续使用Kysely及绑定参数，SQLite JSON路径与特殊表达式集中在驱动适配层。没有添加业务层原生SQL、长时间TTL响应缓存或绕过审核的数据副本。

搜索目前仍为任意子串，扫描规范化文本。资料搜索保持原始Markdown匹配，和统一搜索的去格式、全半角规范化规则各自一致。大范围正文搜索仍随文本总量增长。若将来引入全文检索，应先明确分词、子串、中文和日语的语义及回退方式，再做独立验收。

首次升级、巨量导入后的投影生成和附件完整核查仍有成本；未声称本轮已消除此成本。Android本地WASM使用同一查询及投影规则，实际手机速度需要真机测量。

## 复跑与记录

最终自动化861项、浏览器查询与加载38组以及306个布局样本通过。Web、最终服务端与Android网页资源编译通过，初始静态JS依赖图验证通过。恢复专项同时覆盖资料旧索引升级、磁盘失败回滚、禁止未来索引版本以及清除孤立派生卡片。

在项目根目录执行，性能脚本需彼此串行且避开构建和全量测试：

```sh
npx tsx scripts/qa/check-startup-scale.ts
npx tsx scripts/qa/check-search-scale.ts
npx tsx scripts/qa/check-library-scale.ts
npm test -- --test-concurrency=4
npm run build
node scripts/qa/check-loading-chunks.mjs
node scripts/qa/check-query-experience-ui.mjs
node scripts/qa/check-search-ui.mjs
node scripts/qa/check-layout-ui.mjs --full
npm run mobile:build
node scripts/qa/check-loading-chunks.mjs --mobile
```

浏览器脚本需Playwright及本机浏览器，`PLAYWRIGHT_MODULE`可指定其模块路径。所有浏览器验收完成前不要重建或清理`dist/web`。`check-web-loading.mjs`另起Vite样例，验证StrictMode、取消、配置变化刷新等，不连接工作服务。

性能报告位于`test-results/startup-scale/`、`search-scale/`和`library-scale/`；首次资料方案记录为`library-scale/before-projection.json`，最终为`report.json`。全量日志为`test-results/performance-audit-full-tests.log`，构建日志为`performance-audit-build.log`。验收结论见[验收记录](../../验收记录.md)。这些输出由Git忽略。
