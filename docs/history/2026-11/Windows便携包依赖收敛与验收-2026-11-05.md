# Windows便携包依赖收敛与验收

本轮按“兼容依赖慎删”的原则，收敛Windows一体包中的重复服务端依赖。不移除Electron、独立Node、DLL、语言包或依赖包内部文件，不改变双击启动、离线资源和用户数据目录。所有构建和EXE验收输出到忽略目录`test-results/windows-size-20261105/`，未覆盖既有`artifacts/`发布物，没有访问工作服务4317或工作数据库。

## 测量

| 内容 | 同源码控制包 | 优化包 |
| --- | ---: | ---: |
| ZIP大小 | 275,016,745 B | 220,520,288 B |
| 解压大小 | 696,793,812 B | 522,230,476 B |
| 文件数 | 13,149 | 6,594 |
| 服务端node_modules | 210,754,847 B | 37,310,876 B |

ZIP减少54,496,457字节，约19.8%；解压内容减少174,563,336字节，约25.1%。控制包来自本轮第一次构建，尚未正确裁剪锁文件中的孤立包；最终包采用相同编译资源与运行时。对照两包的650份`resources/server/dist/`文件哈希全部一致，Node.exe、Electron.exe和app.asar也逐字节相同；Node 24.22.0和Electron 45.0.0均未更换。该对照比历史版本更适合评估依赖收敛收益。

已有历史Windows ZIP为276,028,049字节，解压702,743,647字节、13,198文件。它与优化包的差异也包含本轮其他源码／资源变更，不能将全部差值仅归于依赖裁剪。上述数字是本机本轮实测，不代表未来新增功能后的固定包体积。

## 删除与保留决策

| 类别 | 决策 | 依据与验证 |
| --- | --- | --- |
| Electron、Chromium、全部DLL、ICU和语言包 | 全部保留 | 存在跨机器、GPU、媒体、系统语言兼容用途；不按本机启动成功推断其可删。 |
| 独立Node 24与许可 | 保留 | 本地服务使用Node内置SQLite，不能直接假定Electron的Node版本／ABI可替代。EXE在仅含Windows系统目录的PATH下通过。 |
| Fastify、Swagger、KaTeX、Kysely、FSRS、文本解析等服务依赖 | 保留整个npm依赖闭包及包内资源 | Swagger会在运行时读取静态文件，包内资源不能仅按JS导入删减。自动文档、Swagger JS、搜索、迁移往返均实际运行。 |
| React、React DOM、lucide、前端Markdown等在服务node_modules中的副本 | 不再安装这些无服务引用的根依赖 | Windows UI使用`dist/web/`已编译资源，相关渲染能力仍在其中。EXE页面、题库导航和笔记实际验收。 |
| PDF.js及其Node canvas可选原生库的服务副本 | 不再安装 | 全部编译服务／共享代码无Node端引用；PDF.js、worker、CMap与标准字体仍随Web资源提供。EXE上传PDF、读取元数据并实际渲染原文canvas通过。 |
| pdf-lib、fontkit的服务副本 | 不再安装 | PDF生成在Renderer执行，编译后的导出模块和完整离线字体保留。实际EXE生成PDF并确认页数通过。 |
| sql.js的Windows服务副本 | 不再安装 | Windows服务使用随附Node内置SQLite；Android/WASM适配与移动资源没有裁剪。SQLite持久化、交卷与关闭重开通过。 |
| Capacitor等移动专用依赖的Windows服务副本 | 不再安装 | 移动平台源码和根项目依赖不变，Windows服务不引用这些包。未改变Android构建。 |

“不再安装”仅针对Windows服务的重复副本，不是从源项目或相应平台移除功能。若以后服务端真正引用这些包，编译输出中的导入会使其重新进入生产依赖。

## 实现与锁定边界

`scripts/release/windows-server-dependencies.mjs`扫描全部编译后的`dist/server/`和`dist/shared/`，包含命令模块、条件分支里的字面量动态导入、转导出与CommonJS require。复用项目AST解析器，拒绝未声明、未锁定、URL式或非字面量模块加载，并报告路径和行号；不会遇到不确定项后静默删掉。

从14个直接外部包生成独立服务manifest，随后让npm离线规范化锁文件中的可达依赖图。实际发现只改锁文件根dependencies不足以减重：`npm ci`仍会物化旧的生产标记孤立记录。因此必须先离线规范化，再逐条确认所有保留记录的版本、registry URL和integrity与仓库锁完全相同，最后执行`npm ci --omit=dev --ignore-scripts`。最终锁由456条记录收敛到158条，安装157个包；没有重新挑选依赖版本，也没有改根package.json或package-lock.json。

第三方包本身仍完整安装，交由npm保留声明的传递依赖、资源和许可。该检查不能证明任意未来的自定义插件发现、反射或动态代码生成；引入这类机制时必须补明确的依赖声明和发布验收，不能猜测其兼容依赖无用。当前编译服务没有需外部目录提供的插件加载机制。

默认发布位置保持`artifacts/windows/`和`artifacts/releases/`。只做本地核验时可使用隔离输出：

```sh
npm run windows:release -- --reuse-build --skip-checks --output-directory test-results/windows-check
node scripts/qa/check-windows.mjs test-results/windows-check/windows/noetic-atlas-win32-x64/noetic-atlas.exe
```

`--reuse-build`要求先完成构建，`--skip-checks`只供已有验收结果的显式调用；两者不会裁掉运行时。自定义输出仅允许位于项目的`artifacts/`或`test-results/`中，检查已有父路径的真实位置，避免通过链接写到项目外。

## 验证

依赖选择、锁对象不可替换、动态依赖失败关闭与既有架构回归共8项通过。真实优化EXE的13组验收全部通过：无系统Node启动、空库与干净基础配置、Swagger资源、Renderer隔离与sandbox、题目新增审核与计分、统一搜索、笔记、原有Blob下载、manifest ZIP导出／预览／可信迁移导入、Renderer PDF导出、PDF上传及原文阅读、AI关闭无密钥入口，以及关闭后端口释放、重开持久化。

AI只检查关闭状态和本地拒绝调用，不请求供应商。PDF测试内容由验收工具合成，不使用用户文件。最终再将整份分发目录复制到仓库外的系统临时目录，解引用内部链接，EXE和进程cwd均从该副本运行；仍清除NODE_PATH／NODE_OPTIONS等并仅使用Windows系统PATH，避免Node沿分发目录的父级回退读取仓库依赖。相同13项再次全部通过，报告确认`isolatedDistribution`、`executableOutsideCheckout`、`cwdOutsideCheckout`均为true。源分发目录若已有用户data则拒绝复制；测试数据和完整临时应用副本在结束后清理，并确认进程／端口关闭。

证据：`baseline-archive.json`、`control-archive.json`、`final-archive.json`、`comparison.json`、`package-final.log`、`dependency-tests-final.log`、`exe-compatibility.log`、`exe-external-isolation.log`和`external-isolation-report.json`位于`test-results/windows-size-20261105/`；界面截图与详细EXE报告位于`test-results/windows-smoke/`。测试包仍是本地验收产物，未创建GitHub Release或替换用户已有发布附件。
