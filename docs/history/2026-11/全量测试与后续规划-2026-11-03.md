## 本轮修复

| 问题 | 调整及回归要求 |

| 词汇／概念题集从“复习”页签打开专注复习时没有方向选择，顶部入口却有 | 从题集页贯通`practiceKind`，两个入口均可选择正向、逆向或双向 |

## 后续优化优先级

以下是后续建设顺序，区别于本轮已修复的交互缺陷。建议先完成第一批，再选择内容维护或学习反馈中的一条主线。

| 顺序 | 事项 | 价值与可验收结果 |
| --- | --- | --- |
| 第一批 | **词汇卡专用编辑** | 直接维护词头、独立释义、可接受词形、音标／假名，预览两个方向；说明修改只影响新的练习快照。概念卡已有编辑基础可复用，避免为了改一个词形重新导入JSON。 |
| 第一批 | **在线质量扫描覆盖判题标准** | 现批量补全脚本已阻止空列表、断裂代码等，但在线扫描尚未检查`gradingRequirements`。共享适用的Markdown／公式规则，覆盖主观小题；空字段仍合法，非空表达问题进入同一质量问题队列，不自动改题。 |
| 第一批 | **关键交互成为自动合并门槛** | 从现有脚本挑5—8条稳定流程，覆盖保存失败、暂停计时、题集看题、AI取消／迟到、双向标准、备份选择和恢复；完整巡检留给候选发布，统一记录脚本范围与结果，减少人工挑脚本遗漏。 |
| 第二批 | **有界题目编辑草稿与修订历史** | 草稿解决未保存编辑恢复，修订记录解决已保存错误回退，两者分别设计。保留字段差异、修改原因、来源及有限版本；还原原题不重算已有题集和答卷。 |
| 第二批 | **版本化内容包与差量升级** | 在现有自包含分享上增加包身份、内容版本、安装记录；导入前预览新增、更新、移除建议与本地冲突。用户自改不覆盖，更新可回退，避免同ID不同内容只能不断另存。 |
| 第二批 | **AI人审评价集** | 先整理50—100个人工核定样本：词性／义项、全部与部分覆盖、近义非等价、概念边界、公式单位、严格／宽松题集、部分正确、参考不足。记录模型和提示版本，比较误判与评分差异，而不是只判断请求是否成功。 |
| 第三批 | **逐要点判题与补学** | 在评价集稳定后，展示必要点的满足／缺失／冲突／无法判断及作答证据，由用户确认；把具体薄弱点连接到已有资料、近似题和复习任务。先小范围验证，不机械给全库标准拆权重。 |
| 第三批 | **计划的真实时间预算** | 基于实际完成耗时和样本置信度估算每日负担，区分复习占用与新题余量；不把分值固定换算成分钟。已有日计划和统计继续复用。 |

## 可以顺手改善的交互

- AI记录筛选、分页写入受限URL；结果按任务类型复用已有预览组件，结构化JSON保留为高级查看。
- 从答卷“查看原题与学习笔记”进入后，提供明确的“返回本次复盘”上下文。
- 每日计划的任务筛选、分页随URL保留，数据变化后纠正越界页。
- 词汇／概念卡检测相同独立释义和易混目标，提示人工核对区分度；不因两个描述相近就自动改答案。
- 对短概念、普通习题和词卡提供更贴近任务的编辑布局，减少一次显示的无关字段，保留完整编辑模式。
- 手机“数据维护与备份”页优先给出常用备份入口，用锚点或折叠组织清理、分级重置等高级维护；本轮长页样例约4000像素，这属于减少滚动成本的建议。

## 工程与设备验证

当前模块边界、共享判分、ORM和参数绑定、派生索引、事务及恢复保护已有基础，不建议整体重写。后续最需要测量的是Android实际设备：完整SQLite导出、Base64、原生写入及回读，长AI等待期间的请求排队、内存峰值和取消体验。现移动端串行队列及整库持久化有明确成本，但未测量前不下“设备上必慢”的结论。

如网络等待主导，再设计冻结输入后在队列外调用模型、回到队列内核验版本与提交；如完整保存主导，再评估后台工作线程或原生增量存储。每一步保留失败审计、版本冲突、考试锁和落盘失败回滚。资料扩展则优先可检索的文字PDF页索引和选区证据，OCR作为单独可选任务。
