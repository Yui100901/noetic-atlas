# 安卓自适应与工程收敛验收

本轮范围为雷电新分辨率适配、测试脚本整合、工程依赖边界与移动／导出体积优化。测试使用独立`.qa`应用、合成内容和隔离数据库，没有访问工作服务4317、修改工作题库或调用真实AI。未生成正式发布附件。

## 原生自适应

模拟器物理配置为1080×1920、480dpi。开始时仍有上轮390×844测试覆盖尺寸，已取消该遗留覆盖，后续保留当前物理配置。实测竖屏WebView为360×616 CSS像素，横屏为640×336，设备像素比3；另测系统字体1.3倍。

扫描32个页面／入口及7个长表单底部，三组共117个样本，检查横向溢出、同层操作控件重叠、异常提示、抽屉打开关闭。固定保存条与滚动背景的有意叠层不视为同层重叠；表单另检查滚到底部及键盘避让。页面涉及总览、题库、组合题、审核与质量、组题、题集阅读、答卷、专注复习、错题收藏、资料、分类、搜索、统计、分享、AI入口和系统配置。

Android字体变化会重建WebView，测试工具在每组重新连接本次拥有的QA进程。先记录设备原始配置，结束时恢复大小、密度、旋转、系统字体和输入法；Android可能将原本缺省的字体设置写成1.0，按有效默认值比较，同时保留原始证据。只清理固定`.qa`包的数据，不操作正式应用。

最终117个页面／状态样本与1个真实键盘样本通过，零布局发现、页面异常及外部网络请求。键盘弹出后可见高度616→376 CSS像素，保存条仍可见。实际系统分享与导出通过：PDF 8页、6,466,493字节，中文文字可提取；Markdown 4,837字节。测试应用及本地离线输入法已卸载，ADB转发清空，设备配置恢复。

## 测试脚本与工程边界

- `npm run qa`默认执行6项隔离冒烟，CI使用同一清单；`qa:list`列出106项专项。可按组或ID运行、预览命令、串行执行并汇总失败／超时／取消，逐项保留日志。
- 真实AI、工作数据核对、原生设备和发布产物验收须显式选择，不进入默认离线全量。真实AI还需要明确启用开关。
- 共享浏览器工具统一可选Playwright路径、平台channel、服务准备等待和子进程清理；普通／Strict计时、AI导入布局与AI编辑已迁入。保留专项入口便于单独定位。
- 共用AST依赖解析器供架构测试和只读检查复用，约束Shared、Web、Server、Mobile依赖方向，并从Android入口核查Node／Fastify引用确有移动适配。检查涵盖动态／类型导入、转导出及缺失资源，不能替代动态执行产生的依赖检查。
- `qa:android:build`构建固定包名`cn.noetic.atlas.qa`并核对APK身份；`qa:android`使用指定设备运行。QA入口仅存在于专用包，构建结束恢复生产Android资源，发布目录不混入测试桥。

命令、前置条件、设备恢复和报告位置见[测试与验收](../../测试与验收.md)，分层规则见[项目结构](../../项目结构.md)。

## 体积与导出

数据包中的文本分片使用DEFLATE，已压缩媒体与数据库副本保留STORE；容量、实际解压量、路径、CRC与manifest哈希检查保留。PDF按资源地址复用嵌入图片，完整中文字体继续离线提供，解码后字节与原TTF一致。

| 合成测量 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 高重复1000题数据包 | 1,467,931 B | 13,013 B |
| 20次同一PNG的7页PDF | 10,062,127 B | 6,637,537 B |
| 完整字体存储／传输 | 10,596,232 B | 6,308,656 B |

该题包样本重复度高，不能代表实际所有领域包的压缩率。PDF保留完整字体，普通短卷仍可能达到数MB；没有为缩小文件启用已知存在中文字形问题的子集嵌入。

实包发现AAPT会处理`.gz`扩展名，导致字体被展开并更名。因此改为gzip内容的`.ttf.bin`，由前端有界解码；构建会核对APK中的路径与每个原始字节。字体与公式资源并行加载时使用局部Promise，避免字体加载失败清空缓存后被误读为null；浏览器加入503失败、明确错误和再次成功导出的回归。

另修复专用QA打包合并生产资源造成的重复JS：只替换经校验的生成目录，结束时再复制生产资源。该问题属于测试包构建，不是对旧正式发布包重复文件的推断。移动生产目录为16,216,529字节。专用QA输出从空目录构建后，APK为15,805,065字节，含6,308,656字节的压缩字体；与原生验收所用包的452个保留载荷哈希完全相同，仅去除12个旧的未引用资源。该数字属于专用测试包，未据此宣称正式APK的受控收益。按用户后续要求，安卓不再追求压缩极限，后续减重重点转到Windows一体包。

具体实现、完整字体许可及测量方法见[导出与资源体积优化](./导出与资源体积优化-2026-11-05.md)。

## Windows一体包与兼容决策

Windows按用户要求区分兼容必需与纯冗余，保留Electron、独立Node 24、DLL、全部语言资源、许可证及服务依赖包完整闭包；只停止在Windows服务目录安装无服务引用的前端／移动依赖副本。未知动态模块加载会阻止打包，不猜测删减。

同编译资源控制包ZIP 275,016,745→220,520,288字节（约19.8%），解压696,793,812→522,230,476字节；服务端依赖目录210,754,847→37,310,876字节。650份前端／服务编译资源、Node、Electron与桌面壳逐字节一致。真实EXE 13组通过，包括PDF阅读／导出、Swagger、搜索、数据包往返、AI关闭状态与重启持久化。随后将完整分发目录复制到仓库外系统临时目录，清除Node环境变量、PATH仅保留系统目录，同样13组全部通过；报告确认EXE与cwd都在仓库之外，排除回退开发目录依赖的干扰。

具体移除／保留依据、锁文件处理和限制见[Windows便携包依赖收敛与验收](./Windows便携包依赖收敛与验收-2026-11-05.md)。产物位于本地`test-results/windows-size-20261105/package-final/releases/`，未覆盖既有发布附件。
