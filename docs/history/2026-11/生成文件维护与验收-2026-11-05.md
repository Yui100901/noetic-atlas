# 生成文件维护与验收

日期：2026-11-05。范围为构建资源的归属、可重复生成、清理保护、源码包边界及检查入口。没有操作工作数据库、个人配置、正式签名或4317服务，也没有清理旧验收缓存。

## 实现

- `scripts/build/generated-assets.mjs`集中声明Web与Android资源；`generated-paths.mjs`负责文件系统边界，`generated.mjs`提供准备、检查和预览清理入口。保留原构建脚本名称，移动构建移除重复第三方复制步骤。
- 先读取和验证全部输入，再预检所有目标。改变的派生目录重建并移除旧文件；相同内容保持原字节和修改时间，不向构建输入写入当前时间等波动信息。
- 路径检查覆盖根目录、祖先与内部子树，拒绝符号链接／Windows目录联接、非规范路径、设备别名、数据库、签名、私密配置和归档文件。所有目标先预检，避免后一个目录异常时前一个已被清理。
- `generated:clean`默认只预览，`--apply`执行；只接受固定`assets`／`build`／`all`范围。工作数据、签名、工具链、验收证据、发布产物和内容归档不在本入口内，`release clean`保持独立。
- 9份`public/licenses`是受控法律快照，继续提交Git。来源变化可重新生成并审查差异；未知许可文件拒绝自动删除。两份Capacitor Gradle连接文件、原生工程及原始字体继续保留。
- 完整CJK字体、PDF.js的185份字符映射／标准字体及其许可完整保留。字体仍用gzip字节的`.bin`后缀，避免AAPT自动展开`.gz`。这些兼容资源不因当前样本未使用而裁剪。
- 源码ZIP进一步排除`public/fonts`派生副本，继续保留原始字体与OFL；运行包仍包含当前`.bin`字体及离线资源。新增实际ZIP内容断言。
- `npm run check`接入仅源码校验，QA增加`generated`静态检查；CI在Web／移动构建后校验完整资源。新克隆不要求先生成二进制。Git校验只使用项目自身仓库，不误用上层个人文件仓库。
- 固定许可快照和原始字体许可的LF换行。临时Git仓库使用`core.autocrlf=true`验证实际KaTeX、mhchem、OFL三份文件的checkout字节，修复Windows新克隆误报。

操作规则与命令见[生成文件维护](../../生成文件维护.md)。
