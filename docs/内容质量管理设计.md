# 内容质量管理设计

本文件说明已经实现的统一质量管理，并单独列出后续修订能力。日常操作见[使用说明书](./使用说明书.md#全库内容质量管理)，接口约定见[API约定](./API-CONTRACT.md)。

## 审核与质量的职责

题库管理只有两个管理入口：

| 入口 | 负责的判断 | 主要操作 |
| --- | --- | --- |
| 审核管理 | 新增或待审核题能否进入正式题库 | 人工／AI审核、确认发布、退回草稿 |
| 质量管理 | 用户反馈和扫描发现是否成立，当前题目怎样改进 | 证据比对、AI复核、编辑修正、确认／解决／忽略问题 |

反馈核查不再是独立工作台。已审核题可以有待核查问题，质量处理不改变准入审核；没有质量记录也不能证明内容已经专家核验。分类、标签继续表达知识归属、主题和学习用途，不承担质量工单状态。

## 题目汇总与独立问题项

主队列按根题号汇总，一道题只出现一条记录。组合题的公共材料和各小题发现也归到同一道根题下。主页面直接展示题目及题下问题简要行，标明描述、用户反馈或规则扫描来源和状态；详细证据、修改及单项处理集中在题目编辑页。

主列表在数据库中先按题号分组再分页，分页总数是题目数。筛选匹配任一问题项时显示该题；卡片分别给出全题问题项总数、待处理项数与当前筛选命中项数。题下简要列表按视口逐步加载当前页题目的全部来源和状态，避免只筛用户反馈时遗漏同题扫描发现；大量问题独立分页。编辑页本题问题面板另支持状态筛选及分页。全局概览同时区分题目数和问题项数。

每次用户提交反馈，事务内保存反馈原文并建立对应的质量待处理记录。一道题或一个小题可以有多条反馈，各条反馈独立保留；不能因题号、内容或类型相同就吞掉重复提交的证据。

每个问题项统一记录来源：用户反馈或规则扫描。题目汇总是读取视图，不合并或删除底层证据；状态、版本、反馈和AI上下文仍以问题项为单位。不再要求用户先去反馈页确认、再去质量页处理。

反馈和质量问题使用关联ID保持一致，状态、处理说明及版本在事务内同步。用户反馈的 `pending` 对应质量的 `open`，其余 `confirmed / resolved / dismissed` 分别对应已确认问题、已解决、已忽略；扫描证据失效使用 `stale` 表示需重新检查。多个用户反馈各有自己的处理结论，不因关闭其中一条而把同题其他反馈一起关闭。

用户反馈的原文、内容指纹、处理记录和AI复核结果继续保存。题面在证据详情中读取当前原题；发生变化或原题已删除时显示相应提示，不把当前题面伪称为反馈发生时的完整快照。

扫描发现按题号／小题、规则版本、内容指纹和关联候选幂等记录，重扫相同内容保留人工结论。扫描不重建或自动关闭用户反馈，也不覆盖反馈的人工处理结论。

## 当前规则与可选来源

| 检查层次 | 当前检查示例 | 处理边界 |
| --- | --- | --- |
| 结构与资源引用 | 答案引用、题目结构、图片或附件不可用 | 复用结构和资源校验，提供具体位置与证据 |
| 内容完整性 | 空题干 | 缺少独立解析不能证明答案缺少说明，不凭空字段生成问题 |
| 表达一致性 | 重复选项、已知模板占位符、冗余说明、明确答案结论冲突 | 不直接改写答案或重排选项 |
| 反向练习 | 独立概念提示泄露主词或别称 | 保留原始片段供核查 |
| 来源格式 | 已填写来源仍是示例占位地址 | 不把空来源当作问题，不联网遍历全部链接 |
| 重复与冲突 | 精确重复、客观同题不同保存答案 | 展示有限候选，不自动合并或删除 |

参考来源可省略或为空数组。空来源不阻止保存、审核、练习或导入，也不产生质量问题；主动填写的来源仍遵守地址与结构规则。独立解析也可省略；答案中可包含完整解释，不要求重复填写。`missing_source` 和 `missing_explanation` 仅为读取旧备份保留的历史规则标识，不再用于新扫描或检查选项。不会以答案字数、是否含某关键词代替内容质量判断。

填空占位符检查通过Markdown语法树识别，排除围栏、缩进、行内代码、HTML code/pre及转义文本。代码缩进、运算符、大小写、否定词、数字、单位与专业符号不因清理而改变。

严重度分为结构错误、需重点核查和编辑提示。规则检查没有对每题进行专家鉴定，也没有自动核验全部来源。医学、法规等领域不会仅因所属领域统一添加过时标签；时效和事实正确性仍需结合具体证据判断。

## 统一页面与编辑流程

知识题库的“题库管理 → 质量管理”进入 `#/content-quality`。页面以题目及题下简要问题列表为主，扫描设置、扫描历史和批量操作收进“扫描与批量工具”。题目标题、“详情与编辑”及单项“详情与处理”均直接进入已有编辑器；单项入口定位对应问题。旧反馈／质量问题深链解析所属根题后同样进入编辑页，不再保留另一套长详情工作台。

工作台展示有记录的题目数、待处理题目数，以及待核查、已确认问题、需重新检查、已解决及已忽略的问题项统计。主列表按题目分页，题内问题列表也支持分页与每页数量调整。

批量操作明确选择题内的具体问题项，可跨题目和分页保留选择；每批最多100项，AI复核最多20项。不通过勾选整题隐式处理其全部反馈，避免部分问题遗漏或误关闭。

编辑器将质量面板放在正文编辑字段之前。首次进入时，有待核查、已确认或需重查的问题默认展开；无记录或全部问题已处理时默认收起，具体问题深链仍自动展开定位。问题项用颜色与文字区分状态，严重度、来源及小题信息继续单独标明；点击某项可查看反馈原文、扫描说明、站内比较、AI建议和失败原因。

每个问题卡片有自己的处理状态选择、备注和“保存本项状态”按钮，按自身ID及版本提交；不复用兄弟项状态、备注或版本。列表刷新保留按问题ID挂载的交互，不清空其他项尚未保存的状态选择和备注。缺少确认、解决或忽略所需的依据时，点击保存显示本项必填提示并聚焦备注，不提交请求，避免仅有禁用按钮而无操作反馈。详情区域保留证据与AI能力，处理状态在对应卡片保存。

从审核或质量管理进入时，编辑页默认展开题干、选项、参考答案和解析预览，不包含掌握度、学习笔记、历史作答或自测入口。管理列表上下文以规范化的 `returnTo` 保存，仅允许审核和质量管理地址及已知筛选／分页参数；单项定位使用 `qualityIssueId`。保存默认留在编辑页供继续核查，返回恢复原管理列表。审核列表同样默认展开原题及答案，标题和详情直达编辑器；待审核题在编辑页确认通过或退回后返回管理列表。

确认、解决或忽略需填写处理依据，并进行乐观版本检查。原题编辑仍使用已有编辑器：保存并继续处理后可留在原页，重新检查，再按依据更新对应质量状态。未保存正文或远程版本变化会阻止陈旧操作。修改题目、扫描和人工关闭是明确的独立动作，不把保存成功当作全部问题自动解决。

源题变化后，反馈关联的问题可在当前原题及候选已重新检查后标为已解决，不要求扫描先把反馈改为需重查。原反馈指纹和证据保持原样，不以重新签名掩盖版本差异。

## 站内比对与AI复核

用户可在编辑页质量问题证据中展开站内相似与冲突候选，再对本条运行AI复核；批量复核在质量管理折叠工具区对最多20个已选问题进行。模型只使用提交的原题、反馈／扫描说明和有限本机候选，不宣称已经检索互联网。

用户反馈直接复用其上下文；扫描问题首次AI复核时，为原质量问题创建 `origin=quality` 的系统上下文，并关联到该问题。它不是一条新的用户投诉或独立待办，不会因点击AI而在队列里再造一条反馈工单。

AI结果集中保存在关联复核上下文，质量详情直接读取。成立、不成立或暂不确定均为建议，不自动更新问题处理状态、标准答案、准入审核或学习记录。缺图、截断或证据不足时保持不确定；原题、候选或处理状态在请求期间变化时，拒绝陈旧结果。批量处理保留各项成功、失败和诊断，支持失败项重试。

普通查询和确定性扫描不会自动调用模型。AI阅题、待审题发布与人工质量结论分别记录，互不冒充。

## 存储、迁移与历史保护

| 实体 | 权威内容 |
| --- | --- |
| `quality_issues` | 用户反馈或扫描来源、题号／小题、证据、指纹、严重度、关联上下文、状态及处理说明 |
| `question_feedback` | 用户反馈原文或系统复核上下文、反馈版本线索、AI结果与失败诊断 |
| `quality_scans` | 扫描范围、规则版本、游标、批次进度、原始发现计数、失败及完成时间 |
| `quality_fingerprints` | 可重建的紧凑题面、答案与完整内容签名，仅用于候选比对 |

升级、可信JSON合并迁移和原生完整恢复显式、幂等地补齐旧反馈关联。旧反馈数量、原说明和已有结论保留；关联冲突会拒绝写入，不把同一反馈默默挂到不同问题。普通GET不执行补写迁移。

旧 `missing_source` 自动问题在升级和可信导入时删除，不伪造为人工已解决。旧 `missing_explanation` 项仅删除无人工处理说明、无反馈或AI关联的待核查／失效提示；已有人工结论或关联证据原样保留，不进入默认列表和统计，显式深链仍可回看，停用规则不再发起AI复核。`quality_scans` 保留当时的原始计数，因此旧扫描发现数量与当前问题数量可以不同；旧备份导入也不会重新启用缺来源告警。

可信备份和迁移保留反馈、质量问题、扫描记录及处理说明，完整SQLite备份保留AI处理记录。普通分享不默认携带私人反馈、本地管理记录或凭据。派生签名不进入JSON迁移；SQLite完整恢复时也清空重建。旧任务游标前签名缺失时，拒绝直接续跑并要求新建扫描，避免遗漏比对后宣称完成。

题目、学习状态和历史卷面分别保留。质量处理不会重新判分、重写错题依据或FSRS事件，也不会自动替换已经形成的历史作答快照。

## 分批扫描与重复候选

扫描由显式请求推进，每批1—200题，网页默认100题；本批事务提交，失败回滚本批。可暂停、继续、取消和查看历史，关闭页面后已完成的进度保留。

查询使用Kysely数据库边界，先从紧凑投影筛选，再只加载当前批正文。精确候选签名比较题型、题干、选项、判分规则及组合小题，完整重复还比较答案、解析和概念／词卡数据。客观答案冲突比较判分键／空位答案，避免把同一正确答案的不同文字说明误判为冲突。

每题最多比较20条有效紧凑签名，每类问题展示最多5条候选。限定领域扫描只覆盖已扫描、未变化的签名，要建立全库覆盖需完整运行全库扫描。标题相同或语义相似不等于可合并，合理变式、代码符号、单位与适用版本差异都需人工比较。

## 后续设计：修订提案与影响范围

当前修正使用已有编辑器，可通过AI辅助编辑分析当前草稿与质量问题，逐条查看原因及字段差异，单独应用或撤回后再保存。字段已手动改动时拒绝覆盖；AI建议不会替用户确认问题状态。分析记录保留，但表单内的应用与撤回属于当前编辑会话。

后续可增加独立持久化的修订提案、审核及版本发布流程，以及题集影响预览和显式升级；这些不属于当前AI表单辅助编辑已实现能力。

知识含义、正确答案或小题身份实质变化时，需要评估学习状态和题集的影响。修订建议可标明拼写、格式、答案或含义变化，避免将旧记忆直接解释为新内容的掌握。历史复盘的修订提示和独立重判流程也需明确设计，不由扫描顺带执行。

还可建立人工核定样本评估规则误报、漏报和建议修订的正确性，覆盖合理变式、真错误、组合题、缺图和时效题。高错率仅能作为排查线索，不证明题目有错。

## 验收要点

新增反馈立即进入统一队列，一题多反馈不丢失；扫描与用户反馈不会相互覆盖；任一合法处理入口的状态同步；AI复核不新增另一条用户反馈待办或自动下结论；原题与答案默认展开；来源为空不告警，旧提示清理幂等；版本冲突拒绝陈旧操作；迁移和恢复保留人工结论；历史快照、成绩和学习记录不变。
