# 发布与部署

项目`noetic-atlas`，产品“认知星图”。软件交付物只有程序与干净基础配置；首次启动为空库，AI默认关闭且没有预设端点、模型或凭据。题库作为单独附件按需导入。

## 软件、内容与个人配置的边界

软件与题库完全分离。源码ZIP、Web运行包、Windows桌面包、APK和Docker均不带任何题目、领域、分类、标签、学习资料或工作数据库，只附`config/defaults.json`。首次启动由程序建立空库并应用基础默认值；已有数据库和个人配置不受覆盖。题库可作为同一GitHub Release中的独立附件，用户选择需要的领域下载。

| 内容 | Git仓库 | 软件Release附件 | 个人迁移 |
| --- | --- | --- | --- |
| `config/defaults.json` | 唯一公开配置样例 | 随软件提供，不含密钥 | 可单独导入，确认后应用 |
| 本地`data/seed.json`及`data/content-packs/` | 整目录忽略 | 不携带 | 现有题目按领域导出 |
| `data/content-sources/`来源元数据 | 整目录忽略 | 不携带 | 随领域题库包保留 |
| 工作SQLite、备份、`data/desktop/`与本机JSON | 忽略 | 排除 | 私下备份迁移 |
| 常规配置、AI端点/模型等参数 | 存在个人数据库，不入Git | 不携带 | 独立配置JSON，先预览再确认 |
| API密钥/Token | 不入Git | 不携带 | 配置JSON不含密钥，换设备后重新填写 |

`data/`整个目录进入Git忽略；本地文件仍保留，不执行清空。`config/`同样默认忽略，只放行干净基础配置`defaults.json`。发布脚本独立拒绝所有数据路径和其他配置文件，不依赖Git忽略规则来保证ZIP干净。测试使用程序构造的小夹具，干净克隆无需本地题库即可测试和打包。

现有题库使用`npm run content:domains`按7个领域导出多个ZIP，默认输出`artifacts/domain-packs/v1.0.0/`。命令只读取一致性副本，通用已发布题进入发布包，新接收方仍需审核；不包含个人专项、笔记、作答、资料或配置。每个ZIP附自包含分类、标签、图片、来源及许可，JSON按最多500题分包。同一药物跨化学与医学保留同一题号，重复导入可复用。

可用`--domains computer-science,english`选择范围，`--output artifacts/domain-packs/另一个目录`避免混入旧文件。已有生成器和`content:package`仍可用于重建内容来源包；Git源码不携带这些大数据。内容可以放同一Release的独立附件，未来也可单独版本化。官方历史驾驶题尚未核实开放再分发许可，因此驾驶ZIP会注明需确认；其他来源也有各自署名或相同方式共享要求，公开发布时保留来源条款，不能直接套用软件许可证。

## 单独迁移配置

在“系统配置 → 数据与备份 → 配置迁移”导出配置JSON，可选择是否包含AI非敏感参数。文件仅包含系统默认值、记录保留上限、分值规则、复习间隔、上传限制，以及选定的AI端点、模型和请求参数；不含题库、试卷、笔记、AI分析历史或密钥。

另一端选择该文件后先预览字段差异，再确认覆盖当前配置。与完整JSON备份的“已有配置优先”不同，独立配置导入可以明确替换已经自定义的设置。若调低保留上限会删除超限草稿或历史，预览列出数量，另行勾选确认后才应用；预览后配置或待清理记录变化，需要重新预览。

未导入AI部分时保留当前AI配置。导入相同AI接口地址时保留目标设备原有密钥；接口地址改变时清除旧密钥，避免把旧凭据发送给另一服务。文件中的任何密钥字段均不被接受。换设备或换接口后，在“AI辅助”重新填写密钥；本地免密钥服务可以按自身要求使用。导入校验失败不写入任何配置。

完整JSON备份继续用于内容和学习记录合并；SQLite备份用于整体恢复。只迁移配置时无需导出整个学习库。Web、Windows和Android共用这套配置迁移规则。

## 交付物与运行要求

| 产物 | 用途 | 使用者需要准备 |
| --- | --- | --- |
| `noetic-atlas-版本-windows-x64.zip` | Windows 免安装桌面端 | 64 位 Windows 10 / 11，可写的解压目录 |
| `noetic-atlas-版本-runtime.zip` | 网页与 API 服务 | Node.js 24.13 或更新的 24.x；首次安装生产依赖 |
| `noetic-atlas-版本-source.zip` | 开发、修改、各平台构建 | Node.js 24.13 或更新的 24.x 和 npm；按目标准备其他工具链 |
| APK | Android 离线学习 | Android 7 / API 24 及以上；正式包需要签名 |
| Docker 镜像 | 容器部署网页与 API | Docker Engine；Compose 部署另需 Docker Compose |

ZIP 包内的 `release-manifest.json` 记录版本和文件摘要，外部 `SHA256SUMS.txt` 用于核对交付物完整性。构建、签名与真机验收是不同步骤，实际验证范围以[验收记录](./验收记录.md)为准。

## 一键打包入口

源码根目录有 CMD、PowerShell、Bash 三种等价入口，支持交互输入或直接传入目标与选项。入口检查 Node.js/npm，实际构建的首次使用会自动安装开发依赖；`--help`、`-h`、`--dry-run` 不触发依赖安装。

```powershell
.\release.cmd
.\release.cmd windows
.\release.ps1
.\release.ps1 web --dry-run
```

Linux / Bash：

```sh
sh ./release.sh
sh ./release.sh web
chmod +x ./release.sh
./release.sh all --docker-command-only
```

也可自行先执行 `npm ci`，再使用统一 npm 入口：

```powershell
npm run release
```

不传目标时脚本提示输入目标；也支持直接传入：

| 输入 | 行为 |
| --- | --- |
| `all` | 构建当前平台支持的 Web、Windows、Android 和源码包，并尝试构建 Docker 镜像 |
| `windows` | 构建预编译网页与 API，打包内置运行时的 Windows 桌面 ZIP |
| `web` | 构建网页与 API，生成 Web 运行包和源码包 |
| `android` | 构建 Android 正式 APK；没有签名配置时输出 unsigned 包 |
| `docker` | 调用 Docker 构建镜像 |
| `source` | 仅生成干净的源码 ZIP |

```powershell
npm run release -- windows
npm run release -- all
npm run release -- all --dry-run
npm run release -- docker --docker-command-only
```

`--dry-run` 只展示计划。`--docker-command-only` 输出 Docker 构建命令而不执行。`--skip-checks` 仅适用于同一份代码已经完成验收后重新打包，不能跳过公开数据检查。

Windows 桌面包只支持在 Windows 构建机生成。Linux / macOS 执行 `all` 时，Windows 目标记为待构建并提示切换构建机，其余目标继续；单独请求 `windows` 则返回非零退出码。Linux 入口用于生成 Web、源码、Docker 和 Android 交付物，当前不生成 Linux 桌面应用。

`all` 遇到未安装 Docker 时，会标明 Docker 尚未构建并打印待执行命令，其他目标继续打包；不会把这一项记作成功。已经安装 Docker 但构建失败时会记录失败并返回非零退出码。单独使用 `docker` 构建时应先启动 Docker，或者明确指定仅输出命令。当前开发环境没有 Docker，因此 Docker 构建命令已提供，但镜像构建与容器运行尚未验证。

打包机需要 Node.js 24.13 或更新的 24.x、npm 和开发依赖。Windows 首次打包会下载 Electron、独立 Node.js 运行时及生产依赖，需要网络；使用桌面 ZIP 的用户无需这些工具。Android 另需 JDK 21、Android SDK API 36 / Build Tools 36.0.0 与 Gradle；`all` 仍会实际尝试 Android 构建，工具链缺失记为失败。打包结果位于 `artifacts/releases/`，APK 同时保留于 `artifacts/`。`release-report.json` 与 `SHA256SUMS.txt` 只记录本次调用的结果和成功产物，不代表目录中历史文件的状态。

## Windows 免安装桌面端

1. 将 `windows-x64.zip` 完整解压到普通用户可写的目录，例如个人文档中的应用目录。
2. 双击解压目录内的 `noetic-atlas.exe`，使用独立桌面窗口。
3. 关闭桌面程序后，程序管理的本地 API 进程会一并退出。若启动失败，保留日志供排查。

桌面包内置Electron、Node.js 24运行时、生产依赖、网页与API及基础配置，题库为空，不要求用户安装Node.js或npm。桌面窗口连接程序自行启动的本机服务；桌面端不会自动使用另一个正在运行的Web实例。

学习数据库与配置默认位于可执行文件旁的 `data/`，桌面缓存和相关状态位于 `data/desktop/`。该目录需要写权限，不建议直接解压到受保护的 `Program Files`。请完整复制或移动应用目录，不能只复制 `.exe`。不要把已经使用过的 `data/` 加入分享包。

升级前在系统配置中导出备份、退出桌面程序，再将新版解压到新目录，把原`data/`目录复制过去后启动。数据库包含用户设置和学习记录，应另存外部备份。软件不自带或重灌题库。

桌面 ZIP 是免安装交付形式；未使用发布者证书签名时，系统可能显示未知发布者提示。公开分发前可由发布者使用自己的代码签名证书签署应用，不得随交付物分发私钥。

## Web 与 Docker 部署

源码部署：`npm ci`、`npm run build`、`npm start`。Web 运行包部署：`npm ci --omit=dev`、`npm start`，无需 TypeScript 或 Vite。Windows 运行包提供启动脚本。首次依赖安装需要网络，普通学习与本机 PDF 生成随后无需网络。

默认网页 [http://127.0.0.1:4317](http://127.0.0.1:4317)，交互文档 [http://127.0.0.1:4317/api/docs/](http://127.0.0.1:4317/api/docs/)，OpenAPI [http://127.0.0.1:4317/api/openapi.json](http://127.0.0.1:4317/api/openapi.json)。默认只监听本机。通过 `HOST`、`PORT`、`DATABASE_PATH`、`SEED_PATH` 设置服务；数据库目录应可写。电脑和 Android 各自使用 SQLite，通过分享或备份主动交换内容。

在源码目录可使用统一脚本生成 Docker 镜像；手动构建命令形式如下：

```powershell
docker build --tag noetic-atlas:1.0.0 --tag noetic-atlas:latest .
docker compose up -d --build
```

版本标签应与 `package.json` 一致，以脚本输出为准。Compose 卷 `noetic-atlas-data` 保存数据库。镜像使用多阶段构建并以非 root 用户运行。不要在无鉴权条件下把当前本地单用户服务直接暴露公网。当前环境未安装 Docker，不把命令生成等同于镜像或容器验收。

## Android 构建与签名

需要 JDK 21、Android SDK API 36 / Build Tools 36.0.0、Gradle 8.14.3。设置 `JAVA_HOME` 与 `ANDROID_HOME`，或给构建命令传 `--java-root` 和 `--sdk-root`。`scripts/build/prepare-android-sdk.py` 可为 Windows 准备官方指定组件。本机的 `local.properties` 与 `.localtools` 不进入源码包。

```powershell
npm run release -- android
npm run android:debug -- --java-root <JDK路径> --sdk-root <SDK路径>
python scripts/release/verify-apk.py
npm run android:release -- --java-root <JDK路径> --sdk-root <SDK路径>
```

Linux 使用相同 npm 目标或 Bash 发布入口，不需要安装 PowerShell：

```sh
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME=/path/to/android-sdk
sh ./release.sh android
npm run android:debug -- --java-root "$JAVA_HOME" --sdk-root "$ANDROID_HOME"
```

`scripts/build/android-build.mjs` 是跨平台 Android 构建入口，按平台调用 Gradle Wrapper；首次构建需要联网获取 Gradle 与 Android 依赖。

统一 release 的 `android` 目标生成正式构建。调试包可单独运行 `android:debug`，输出 `artifacts/noetic-atlas-debug.apk`，仅用于安装测试。正式构建在未配置签名时输出 `noetic-atlas-release-unsigned.apk`，签名后才能安装。通过环境变量 `ANDROID_KEYSTORE`、`ANDROID_STORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 传入正式签名；配置完整时生成 `noetic-atlas-release.apk`。不得把凭据写入仓库、命令日志或文档。

构建会重新打包页面、公开题库、SQLite WASM、PDF.js、中文字体和许可证。`verify-apk.py` 检查实际 APK 字节与最终构建资源一致，并确认没有远程 `server.url`。另使用 SDK 的 `apksigner verify` 核验签名。脚本成功不表示已经完成设备安装验收。

安装新版前先备份。只有相同应用 ID 与相同签名才能直接覆盖升级；清除数据或卸载会删除应用私有学习库。正式发布需在设备上验证系统文件选择、导出分享、AI 联网、前后台恢复和考试到期行为。

## 新版发布、升级与回滚

1. 更新 `package.json` 与 lock 版本；Android 同步 `versionName` 并递增 `versionCode`，保留应用 ID 和正式签名。
2. 更新使用说明、API 文档与验收记录，完成自动化检查及目标平台验证。真实 AI 测试为可选联网验收，凭据不写入发布文件。
3. 执行相应 release 目标，核对 manifest、SHA256 与输出状态；明确区分未构建的 Docker、未签名 APK 与可运行产物。
4. 更新前导出一致性 SQLite 备份及需要的 JSON 备份，放在程序目录外；停止服务或退出桌面程序。
5. Windows保留`data/`，Web指向原有`DATABASE_PATH`，Docker保留持久卷，Android使用相同签名覆盖安装；不要把基础配置或题库包强制覆盖导入已有库。
6. 核对页面、接口、题量及一份代表性历史作答。回滚时停止新程序，用旧程序和升级前数据库副本成对恢复。

## 首次发布到GitHub

以下操作都在`noetic-atlas`项目目录执行，不在外层简历与规划目录操作Git。当前项目已经初始化独立Git仓库，尚未配置远程地址；下面命令中的账号和仓库地址由发布者替换。

1. 核对版本号，运行`npm ci`，执行对应平台发布命令。Windows可用`release.cmd all`或`release.ps1 all`；Linux使用`sh ./release.sh all`。不构建Docker时加`--docker-command-only`。Android正式安装包需配置自己的发布签名，未签名包不作为可安装版本上传。
2. 运行`npm run release:prepare`，从本次成功构建报告中核对SHA256并生成全新的`artifacts/github/v1.0.0/`。目录已存在时拒绝混入旧文件，可用`--output artifacts/github/v1.0.0-第二次`另建目录。它只收集软件ZIP及已签名正式APK，排除调试/未签名APK、扩展内容、工作数据和配置；Docker待构建不会伪装成附件。
3. 检查该目录中的`release-files.json`、`SHA256SUMS.txt`和`RELEASE-NOTES.md`。发布说明可直接作为草稿正文，补充本次变更和实际平台验证范围。此命令不推送Git，也不调用GitHub。
4. 在GitHub创建空仓库，选择可见性和软件源码许可证。当前项目未擅自添加统一软件许可证；若希望以开源软件发布，先确定许可证并添加`LICENSE`，重新生成源码包。题库和第三方资源继续使用各自来源条款。GitHub的[仓库许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)介绍了源码公开与许可证的区别。
5. 在本地检查待提交文件并提交、推送。不要强推覆盖已有远程仓库；以下示例用于新建空仓库：

```sh
git rev-parse --show-toplevel
git status --short
git add .
git diff --cached --stat
git commit -m "Release Noetic Atlas v1.0.0"
git branch -M main
git remote add origin https://github.com/你的账号/noetic-atlas.git
git push -u origin main
git tag -a v1.0.0 -m "Noetic Atlas 1.0.0"
git push origin v1.0.0
```

6. 打开GitHub仓库的Releases，创建`v1.0.0`草稿，将待上传目录内的软件附件、`SHA256SUMS.txt`和`release-files.json`逐个附上，正文使用`RELEASE-NOTES.md`。再从`artifacts/domain-packs/v1.0.0/`挑选所需领域ZIP作为同一Release的独立附件，附上`domain-manifest.json`与`CONTENT-SHA256SUMS.txt`；内容与软件校验文件使用不同名称，避免附件重名。软件ZIP里继续保持无题库。检查附件后发布。不要直接把整个`artifacts/releases/`拖进去，其中可能有历史构建、调试包或未确认许可的内容包。操作入口见[GitHub创建Release说明](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。

也可在安装并登录GitHub CLI后创建草稿，附件仍应明确列出：

```sh
gh release create v1.0.0 --verify-tag --draft --title "认知星图 v1.0.0" --notes-file artifacts/github/v1.0.0/RELEASE-NOTES.md
gh release upload v1.0.0 artifacts/github/v1.0.0/noetic-atlas-1.0.0-source.zip artifacts/github/v1.0.0/noetic-atlas-1.0.0-runtime.zip artifacts/github/v1.0.0/SHA256SUMS.txt artifacts/github/v1.0.0/release-files.json
```

如果同时构建了Windows或正式签名Android，再通过`gh release upload`追加对应附件。最后在网页检查并发布草稿。参数含义见[GitHub CLI release create](https://cli.github.com/manual/gh_release_create)。后续版本重复构建、准备、打标签与上传流程，更新版本号及发布说明。

## 发布边界

只分享生成的干净 ZIP、明确选定的 APK 或镜像。工作数据库、个人资料、审核建议、草稿、AI 配置、签名、测试产物和开发缓存均不随发布包分发。公开题库检查拒绝个人内容、学习历史、配置对象与密钥；跳过测试也不能跳过这项检查。

内容分享与 JSON 备份不含 AI 凭据，系统下载的 SQLite 备份会清除凭据；自行复制的原始工作数据库可能保存用户设置的凭据。原始数据库、签名私钥和本机备份应由用户私下保管。原有个人内容位于项目之外的私人归档，发布包不包含归档路径或内容。
