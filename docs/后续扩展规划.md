## 已具备的基础与判断边界

已具备题库与题集、组合小题、计分与考试、草稿历史、资料库、配置迁移、JSON分享／迁移、Android SQLite完整恢复、统一搜索、每日推荐、FSRS、统计周报，以及AI解析／判题／审核／推荐／教材出题。后续应扩展这些能力的深度，避免重复新增同类栏目。

本轮620项自动化、28个浏览器脚本／241组检查通过，说明所覆盖的业务规则和交互符合预期，不等于31,811道题逐题语义正确、所有教材都可解析，或所有设备都能流畅运行。

当前缺口包括：语义章节自动切分仍需完善、无OCR、教材题缺少结构化资料页段关联，以及Android真机安装和系统行为验收未完成。持久化分批任务及Web、Windows实际发行包验证已完成；历史AI异常证据和后续回归分别保留，不把后续成功追认为早期失败的确定原因。

另有两个应测量后再决定改造规模的风险：Android整库导出／保存及附件增长；大题库和长历史下的冷启动、检索与统计成本。现有证据不能据此断言SQLite或Kysely已经成为瓶颈。

## 1. AI从“能完成”到“失败可解释、可恢复”

本轮14次真实调用出现一次格式异常，受控重放通过。这个样本不足以估计线上失败率，也不足以把异常归因到模型、网络或解析代码。

建议先补每次请求的任务ID、操作类型、模型、提示模板版本、阶段、耗时、HTTP状态、结束原因、输入／输出字节数及可获得的用量。默认仅保存诊断元数据；原始正文诊断由用户主动开启，截断、脱敏并设置保留上限，不记录密钥或请求鉴权头。

失败、取消和成功分开记录；失败记录不能带成功结果，也不能被用于判分或发布。页面给出“重试本次操作”，按任务身份关联历次尝试。网络暂时错误可配置有限重试；取消、非法输入、审核不通过和源版本冲突不能盲目重试。格式错误先提供一次显式重试，继续使用严格JSON与业务校验，不自动猜补答案。

模型生成与本地确认应用应分别幂等：允许用户再次请求一个建议，不意味着允许同一建议重复入题、追加笔记或计入FSRS。

同时按任务缩减发送上下文，例如教材出题只携带相关领域所需的分类标签摘要，而非整棵分类树；发送范围与模型用量应可查看。

验收：模拟网络中断、截断、空响应、非法JSON、重复点击、取消和版本变化，均能显示正确状态；重试不重复应用，诊断导出不含凭据或默认保存的私人正文。

DeepSeek官方文档仍要求JSON提示和合理输出上限，并注明可能出现空内容；这些说明支持继续保留本地校验，不能作为本次未知异常的原因证明。[官方JSON输出说明](https://api-docs.deepseek.com/guides/json_mode/)

## 2. 整本教材按章节处理

当前文本PDF提取与教材出题已验证，但244页原书触发150页限制，需要外部裁剪。建议加入页码范围、目录／章节选择和提取预览，先解决文字教材，不先扩大单次输入和输出上限。

以“教材处理任务”组织工作：读取 → 确认章节 → 分块 → 分配题量 → 生成 → 跨批校验 → 预览 → 确认待审。显示已完成章节、题数和失败批次；允许暂停、取消、仅重跑失败批次和关闭后继续。章节预算需同时控制文本字节、输出长度、总题量和模型调用量。

需要断点恢复时，用户明确选择将材料保存到资料库，任务引用冻结的资料版本与分块。临时粘贴的单次操作仍可保持不保存正文，不能一面不保留任何输入，一面承诺关闭后恢复。

先用SQLite任务表和受限并发执行器即可，无需引入独立消息队列。所有新题继续待审核，取消与失败不把半批结果自动发布；已完成批次可作为待确认成果保留。

验收：整本244页教材在选定范围内分批处理，中断重开后只继续未完成批次，成功批次不重新提交；总题量不超预算，跨批精确重复可被发现。失败批次重试可能额外消耗模型用量，应提示。OCR、拍照识题、多栏／表格／公式识别作为下一阶段，识别不确定处必须可人工校对。

## 3. 资料与题目双向关联

当前来源名称和URL能追溯书名，但不能可靠跳回本地资料的具体页段。建议增加资料版本、内容哈希、PDF文件页码、印刷页码、段落锚点和必要的短依据片段。

从题目可打开原资料相应页；从资料章节可查看已生成题目及覆盖情况。先允许人工核对并固定页段，不把模型编出的页码直接当成已验证定位。原资料替换或删除后，保留旧出处版本说明，不把旧题自动指向新内容。

来源、许可与识别说明放在资料信息、包清单或折叠的出处区，题干继续只展示作答必需信息。题集和已交卷仍使用冻结快照。

验收：本批生成题均能定位支持答案的真实页段；更新原书后旧题出处不漂移；导出分享能携带出处元数据，是否包含原书附件另行选择。

## 4. 内容质量管理与修订

具体流程、数据与历史保护方案见[内容质量管理设计](./内容质量管理设计.md)。

功能测试与AI审核不能替代语义正确性检查。建议建立质量筛选视图：待核验、疑似重复、答案冲突、缺图、来源过期，以及用户反馈的问题。参考来源可选，留空本身不构成质量问题；需要来源支持的具体主张可由用户反馈核查。

先实现全库及跨批精确去重，再做相似题候选。相似题可能考查不同条件，不能自动合并或删除；需要查看题干、选项、答案和适用条件的差异。

题目修改保留修订原因、来源依据和差异，现有题集／历史快照不被重算。过时标记针对依赖版本、法规或指南的具体事实，记录核查日期，不对稳定概念或整个医药领域一律标记。追问、误区应与该题知识点相关，避免重复套用通用模板。

增加一套经人工核定的小型AI评价集，覆盖各题型、部分正确、材料不足、组合题和易混淆概念。分别统计结构成功率、答案正确性、来源支持、评分一致性和不确定判定，不把“HTTP成功率”当成教学质量。

验收：可复现重复／冲突样本并处理；错误修订可追溯；模型或模板变更后能比较同一评价集；内容修订不修改旧成绩与复习事件。

## 5. 数据增长与移动持久化

Android当前写操作前后会整库导出并保存，附件也在SQLite内。这是已确认的实现成本，尚未测得设备容量上限。

先使用合成隔离库分开增加题目、PDF／图片、题集快照和作答历史，测量冷启动、单次保存、内存峰值、导入、备份和恢复。可采用3万／10万题及不同附件体积作为测试档位，不能把这些档位写成已支持容量。

若附件是主要成本，优先抽象资产存储，评估独立文件、内容哈希去重和统一清单；迁移、备份、分享和引用保护须一起设计。若即使小附件也因整库写入变慢，再评估原生SQLite等增量持久化适配，共用Kysely业务查询与判题规则。

不因未来可能增长就立即更换数据库。实际采用网络数据库时仍需要异步执行、事务和方言的实库验证，不能只改连接地址。

验收：在声明支持的真机档位上记录保存与恢复预算，失败回滚和重启后数据完整；存储方式改变后，完整备份仍能搬迁所有题目、附件与学习状态。

## 6. 知识点与学习路线

领域回答“属于哪门知识”，分类回答“如何组织”，标签用于筛选；知识点则表示可复用的概念或技能，例如“变量绑定”“条件概率”。题目可以覆盖多个知识点，并注明主要考点与前置知识。

学习路线组织章节、资料和已有题集，不再复制一套题集或学习记录。先学习材料，再做章节诊断；结合知识点表现推荐补学资料和巩固题，并解释推荐原因。

继续复用FSRS安排单题复习。路线完成度、知识点表现与记忆排期分别计算；未学、未判、样本不足和真正薄弱不能混为一类。当前周报可扩展路线覆盖及补学结果，不重新建另一套统计口径。

验收：能用一本教材建立章节路线并串联资料、诊断题集与复习；缺证据时明确显示未知，不仅凭一道题或自评就宣称掌握整章。

## 7. 内容包升级与跨设备能力

已有分享和迁移是基础。下一步先扩展内容包标识、版本、题目修订、内容哈希、依赖和升级预览；用户能看到新增、修改、删除建议及本地冲突，选择采用哪些修订。来源审核情况与目标设备的审核策略分别处理。

分享新增仍按现有规则待审核，可信迁移保留原审核状态；更新已审核题目时明确呈现修改及重审规则，不能把内容升级伪装成迁移绕过审核。

再考虑只交换学习状态：稳定事件ID、来源版本、设备身份、删除标记和显式冲突规则先确定，保证合并不重复计数、不重复FSRS反馈，也不把已删除内容静默复活。AI密钥保持设备私有。

自动同步作为更后阶段，可从用户控制的文件交换开始，再评估网络服务。不要直接同步或覆盖正在写入的SQLite文件；SQLite官方说明事务期间普通文件复制可能产生不一致副本，应用应继续使用一致性备份与既有恢复边界。[SQLite备份与损坏说明](https://www.sqlite.org/howtocorrupt.html#_backup_or_restore_while_a_transaction_is_active)

验收：两设备离线作答后交换数据，统计及复习不重复；不同题目修订有明确预览，删除冲突可解释；中断交换后原数据可继续使用。

## 8. 实际发行验收与持续回归

下一次发布前，使用真实签名APK和Windows便携包，走一次干净安装 → 导入题库 → 练习 → 备份 → 恢复 → 升级。Android重点测试文件选择、系统分享、拒绝权限、后台／锁屏、系统回收进程、低存储和考试跨后台到期。恢复后继续复用绝对期限与幂等交卷规则。

Capacitor提供前后台、恢复及返回键事件，可作为生命周期接入点，但监听事件本身不保证应用在后台持续运行。[Capacitor App官方文档](https://capacitorjs.com/docs/apis/app)

把现有离线单元／集成、类型检查、Web与mobile顺序构建、文档、空发布数据和核心浏览器验收接入CI。真实模型评价单独手动触发，限制调用预算，不依赖个人工作数据库；发布产物另做实际安装冒烟检查。

性能基准区分冷启动与预热，固定隔离数据、设备和资源竞争条件，记录分位数、响应体积、解析／渲染／持久化成本。当前小样本接口中位数不能作为跨设备性能承诺。

## 建议实施顺序

1. **发布质量与可诊断性**：补实际发行验收、AI失败元数据、显式重试和固定容量基准；将现有确定性回归接入CI。
2. **教材学习主线**：资料版本与页段定位、选页／章节、批处理任务、跨批去重和确认待审。先完成文字PDF，随后评估OCR。
3. **内容与学习深度**：质量修订视图、人工核定评价集、知识点、章节诊断及学习路线；按基准决定资产与移动存储改造。
4. **分发与多端协作**：版本化内容包、学习状态交换，最后再做自动同步和更重的专业练习能力。

近期可交付的最小组合是：**AI失败可追溯 + 教材选页分批 + 题目返回原文页段**。它能直接延伸本次已经验证的教材出题场景，并为后续知识点和学习路线提供基础。
