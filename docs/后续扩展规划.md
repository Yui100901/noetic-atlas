# 认知星图后续扩展规划

更新日期：2026-10-30。依据当前2.0代码、最近一次题库导出及已保存的验收记录重新排序。本文件是后续建议，不代表下列功能已经实现，也未在本轮重新进行全量测试。

## 当前基础与主要判断

已具备题库与题集、组合小题、计分与考试、各类草稿、单题历史、错题与收藏、每日推荐、FSRS、统计周报、统一搜索、资料库、分享与迁移、Android SQLite完整恢复，以及AI解析、判题、编辑建议、审核、相似题、推荐组题和持久教材分批任务。上述能力不再列为新建待办。

最近一次完整领域导出包含23个领域、37,400道独立题目，其中60道题跨领域归属。这是本地内容快照，不是软件内置数据或容量承诺。软件与题库继续分开发布。

近期重点应是提高连续学习效率、让内容能够长期维护，以及巩固移动端和页面回归。优先复用已有题集、学习状态、FSRS和质量管理，不重复增加同类栏目。题量增长之后，修订、出处和容量管理的收益通常高于继续扩张导航和一次性增加大量题目。

## 建议优先级

“小／中／大”表示相对改造范围，不是工期承诺。P0是稳定性和测量；P1是直接延伸现有使用流程；P2按实际需求再推进。

| --- | --- | --- | --- |

| P0 | Android真机与容量基准 | 测量大题库、附件及历史增长后的启动、保存、恢复和进程回收 | 测量中；存储改造待定 |
| 已完成基础 | 数据健康与可控清理 | 已有健康摘要、预览清理、空间整理、索引重建及分级重置；待补恢复副本账本与教材任务清理 | 基础已验收 |
| P1 | 题目修订与题库包升级 | 保存修订差异，按内容版本预览新增、更新、移除建议与冲突 | 中至大 |
| P1 | 学习计划时间预算与周目标 | 多领域日计划已交付；基于真实耗时扩展时间估计、周目标与考前安排 | 中 |

## 先巩固稳定性和数据规模

### 核心UI自动回归

源码检查已经在push和PR执行；浏览器流程当前仅在手动工作流中执行3个脚本，并未把全部已有浏览器验收设为自动门槛。下一步选择少量稳定、高收益路径进入PR检查，完整检查用于候选发布。

优先覆盖：错题／收藏／复习从列表进入和直接打开链接、刷新与前后题导航；练习退出后计时暂停和草稿恢复；组题与长表单离开保护；失败保存后的输入保留；审核及质量状态的独立操作。

布局检查要同时覆盖冷开和热导航、窄屏、暗色、长题名、组合题和逆向任务。继续坚持组件自带样式，不依赖访问过别的路由。保留截图、计算后的布局数据和失败诊断，不仅检查页面是否出现。

当前依据：`.github/workflows/ci.yml`、`.github/workflows/ui-smoke.yml`、`scripts/qa/check-learning-reader-layout-ui.mjs`。最近一次特殊题集验收覆盖59个布局样本；它不等同于全部页面或全部设备验收。

### Android真机与容量基准

已有3万题启动／查询和千本合成教材的性能优化及报告，见[性能核查](./history/2026-10/性能核查-2026-10-29.md)。下一步将这些脚本固定为可比较的基准：区分冷启动、首次索引和预热；提高采样量后记录P95、响应大小、内存峰值和版本变化，再制定门槛。

当前移动实现的有效写操作会在操作前后导出整库；保存还涉及Base64转换、临时文件及提交文件回读校验。这是已确认的实现成本，实际手机上的耗时、内存上限及可接受容量仍需测量，不能直接归因为SQLite或ORM瓶颈。

使用隔离数据分别增加题目、图片／PDF和历史快照，覆盖连续答题保存、导入、备份、完整恢复、锁屏／后台、进程回收和覆盖升级。已有Windows实际发行包验证继续复用；Android签名／静态校验不能替代真机验收。

若主要成本来自附件，先评估资产存储抽象、哈希去重和文件化存储；若主要成本来自整库持久化，再评估原生增量存储适配。保留现有事务、失败回滚、恢复校验和跨端业务边界，依测量结果决定改造。

### 数据健康与清理

已在“系统配置 → 数据维护与备份”交付健康摘要、数据库一致性检查、未引用附件与旧草稿／历史的清理预览、独立AI历史清理、空间整理、索引重建、最近维护摘要，以及全部／题集／单题自测的分级重置。普通清理保留累计学习证据；题集重置保留共享笔记与其他来源，详见[使用说明](./使用说明书.md#数据维护与分级重置)。

后续优先补充恢复前副本和缓存的空间账本、成功备份／验证记录，以及已完成教材任务的引用依赖清理。当前教材任务及关联AI记录受到保护，不应将其“可续处理”状态误作垃圾。文件化存储和压缩策略仍应以真机容量测量决定。

## 下一阶段产品主线

### 题目修订和内容包差异升级

当前人工编辑覆盖现有原题，以updatedAt检查冲突；AI辅助编辑支持当前会话内逐条应用和撤回，但还不是完整的内容修订档案。现有分享对同题号不同内容采用另存，适合安全分享，不能直接替代官方题库升级。

建议先增加稳定修订号、内容哈希、修改原因、字段差异与回退入口。内容包增加独立包身份、内容版本和安装记录，版本不必跟随软件版本。升级先预览新增、更新、移除建议和本地编辑冲突，允许选择应用，保留当前分享新增需审核、可信迁移保留审核状态的区别。

题集及已交卷继续使用冻结快照。修订标准答案不自动改写旧分数、旧错题依据或FSRS事件；可以提示哪些题集引用旧版本，由用户显式调整。内容含义实质变化时，也需要单独决定是否重新评估学习状态。

### 专注复习和多领域日计划

专注复习已实现：题集练习模式和到期队列可启动连续回忆，保留实际作答与心答自评的区别，支持草稿、暂停计时、总结与FSRS排期。操作见[使用说明书](./使用说明书.md#专注复习)。

已交付的专注流程为：回忆 → 核对 → 评级 → 下一项，包含组合小题、词汇／概念顺逆向及键盘／触屏操作。多领域日计划也已接入，复用相同学习事件更新任务进度。

多领域计划已支持领域／分类／标签、学习日期、优先级、权重或固定预算、目标题集、连续专注复习、独立进度、跨日补做与周报。操作见[学习计划说明](./使用说明书.md#多领域学习计划)。后续可扩展真实耗时估计、周目标、考前节奏和可解释的AI计划建议；时间目标应根据实际数据估计，不能直接把不同领域分数换算为分钟。

### 资料页段定位和PDF全文检索

题目与原文互通已交付：稳定资料ID与内容版本、Markdown段落高亮、PDF文件页阅读、资料反查题目、手动引用、AI自动来源及旧任务补关联，见[操作说明](./使用说明书.md#题目与教材原文互通)。

当前来源范围由本机提取和选择保存，不采用模型编造的定位。后续可增加逐题更细的证据片段、人审核对状态和PDF选区。

当前统一搜索的PDF范围为元数据，未包含PDF全文。可先为文字PDF建立按页文本索引，并在搜索结果提供命中片段和跳页；Markdown复用段落锚点。原文定位已支持网页与Android应用内按文件页阅读，可复用现有跳页与返回位置。先用已有本地检索边界，是否引入语义检索再用查询样本判断。

### 公式和专业表达

已接入remark-math、KaTeX与mhchem，支持按内容启用、行内和独立公式、单位及化学反应、编辑模板、预览和源码复制。旧内容不自动改写，来源版本和历史快照保留模式。

网页与离线资源统一使用本地字体；MD/JSON保留源码，PDF保留正文文字并嵌入高清公式。语法检查与科学性复核保持独立。参见[操作说明](./使用说明书.md#公式与专业表达)。后续按实际题型增加公式模板、特殊记号和OCR核对工具；代数等价判分应另立契约，不能从显示支持直接推导。

### AI质量评价与针对性补学

错误诊断、流式过程、失败记录、分批任务与编辑建议已经实现。下一步重点从“请求能完成”推进到“生成内容和评分可靠”。

先选择50—100道人审样本，覆盖各题型、组合题、部分正确、证据不足、缺图、合理变式和常见误解，固定输入及预期标准。模型或提示模板变化后，分别比较结构通过率、事实／答案正确性、评分一致性、来源支持、误改率与用量，不只计算HTTP成功率。

随后可把已判错题整理成“错误原因 → 一两道针对性变式 → 再次验证”的补学链，复用相似题和既有题集。模型建议保持可核对；高错误率只是排查线索，不足以证明题目有错或学习者不理解整个领域。

## 再后续的扩展

| 方向 | 最小可用形态 | 开始前的依赖 |
| --- | --- | --- |
| 音频与语言练习 | 单词发音、听写，再扩组合听力；音频随包离线使用并保留来源 | 通用音频资产、播放模型及来源许可 |
| OCR与拍照识题 | 先提取可编辑文本和图片，人工核对后再生成候选题 | 页段定位、异步任务；表格／公式需单独验证 |
| 知识点和学习路线 | 资料章节关联知识点与既有题集，显示覆盖和补学路径 | 来源稳定、内容质量；样本不足显示未知 |
| 学习状态增量交换 | 先导出学习事件包，在另一设备预览合并 | 复用已有ReviewEvent身份，补设备、删除和冲突规则 |
| 自动跨端同步 | 用户可控制的增量交换与冲突恢复 | 内容修订和学习事件交换先稳定 |
| 编程实作 | 代码编辑、样例测试，再评估受限执行 | 独立执行隔离，不在主应用进程执行任意代码 |
| AI任务配置档案 | 按解析／判题／教材处理选配置、预算与模板版本 | 有实际任务质量或成本差异后再引入 |

备份与同步保持不同职责。自动备份继续使用已有一致性快照边界，不直接复制正在写入的数据库；SQLite提供[在线备份与VACUUM INTO机制](https://www.sqlite.org/backup.html)。跨设备同步优先交换有身份的内容与学习事件，而不是双向覆盖整个数据库文件。

## 推荐实施顺序

1. 先把关键页面冷开／刷新和保存流程加入自动回归，同时完成Android真机及容量测量。
2. 日常使用主线在已完成的多领域计划上扩展时间预算与周目标；维护主线先做题目修订、题库包差异升级与空间管理。
3. 在已完成的原文互通上补PDF正文检索，公式显示已完成，保留跨端回归。
4. 用人工评价集衡量AI质量，再根据真实学习需求选择音频、OCR或知识路线。
5. 内容版本和事件合并规则稳定后，再开展自动同步、在线题库分发或更重的编程执行功能。

如果只选择一项近期产品扩展，建议在多领域日计划基础上扩展时间预算与周目标；如果以持续更新和公开发布题库为主，建议先做题目修订与内容包升级。两条主线都复用现有页面和数据，避免再次堆积入口。
