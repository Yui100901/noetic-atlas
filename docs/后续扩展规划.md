# 认知星图后续扩展规划

首次正式 1.0 定版以 [1.0 发布清单](./1.0发布清单.md)为准。原 3.0 计划已并入首发，不再作为后续扩展目标。本文保留此前的候选方向和技术取舍，作为维护期备忘；后续小版本先修缺陷、改进性能和易用性，不自动启动新功能。

更新日期：2026-11-07。依据当前源码、两轮平台与工程验收及生成文件维护结果重新评估。本轮实现统一导入查重、时间预算与周目标、AI实际用量统计；其余方向按表中状态区分。验收结果见[本轮记录](./history/2026-11/导入查重与学习目标及AI用量-2026-11-06.md)。

## 当前判断

题库、题集、练习／考试、专注复习、FSRS、多领域日计划、统计、资料、统一搜索、质量管理、题目草稿与修订、教材引用、AI辅助以及跨端迁移的基础闭环已经齐全。判题标准在线扫描、Android完整恢复、雷电原生流程／布局验收、Windows合理减重和生成文件维护也已完成，不再列为新建待办。

最近一次全量记录为1,384项：1,380通过、4项按可选内容包跳过、0失败，见[验收记录](./验收记录.md)。这证明已覆盖流程通过，不代表任意容量、设备或全部题目事实均已核验。雷电模拟器验收和实际手机上的容量／内存验证继续分别记录。

下一阶段应提高首次上手、长期使用和持续更新的质量。继续沿用当前TypeScript、React、Fastify、Kysely与SQLite，以及共享业务／平台适配的工程边界。先用实际测量决定存储改造，保留已验证的兼容资源及恢复保证。

## 近期优化

### 首次使用与升级体验

软件以空题库发布，内容包单独提供。首次使用引导已实现：没有内容时显示“导入内容包／自己建题 → 通过审核 → 创建题集并开始第一次练习”，已有内容后使用普通首页，不新增常驻栏目，也不强制配置AI。后续按实际使用反馈维护入口和失败后的恢复提示。

Windows保数据更新使用解压新程序并接续已有`data/`的明确流程，见[更新说明](./发布与部署.md#新版发布升级与回滚)。1.0首发先验证程序替换、数据目录保留、冷开与重启，后续小版本复用该验收。若今后增加自动更新，仍须先备份并保证失败时可恢复。

便携ZIP升级需要独立设计。Electron官方自动更新依赖对应的分发形式，不能把普通便携ZIP视为已具备Squirrel更新条件，见[官方更新说明](https://www.electronjs.org/docs/latest/tutorial/updates)。首版以可核对的手动升级辅助为宜。

### 恢复副本和运行空间管理

现有数据健康、未引用附件／草稿／历史清理、空间整理、索引重建和分级重置已经交付，继续使用原页面。具体缺口是：`mobile/storage.ts`每次恢复创建独立副本，但索引只保留最近一份；`maintenance/health.ts`和当前健康契约主要统计库内记录，无法逐个管理旧恢复副本。

先补可枚举账本，显示副本日期、字节数和最近验证结果，提供下载、预览清理及保留策略；至少保护最近有效副本。后续按需纳入应用导出临时文件与教材任务占用。已完成教材任务清理也必须先处理题目来源、批次候选和AI证据的引用依赖。

这是应用运行数据的维护能力；开发资源仍按[生成文件维护](./生成文件维护.md)处理，发布产物继续使用独立`release clean`。

### 自动回归与可比较性能

现有源码CI会执行检查、全量自动化和两端构建；6项浏览器冒烟已共用清单，但`.github/workflows/ui-smoke.yml`仍仅手动触发。可按前端／共享规则改动自动运行这6项，对关键计时、保存失败、草稿恢复与冷开导航逐步补齐。107项专项清单继续按需求或候选发布执行；真实AI、工作数据和设备访问保留显式边界。

在既有布局检查上加入键盘焦点、屏幕阅读器标签、非颜色状态表达和对比度核查。自动扫描只覆盖部分问题，需保留少量人工操作检查，见[Playwright无障碍测试说明](https://playwright.dev/docs/accessibility-testing)。

当前规模脚本主要使用少量样本的median／max。下一步固定数据集、Node与设备信息，将冷启动／首次索引／预热分开；增加足够样本后再记录P95，并记录内存、响应大小和加载行数。PR先约束重复查询、全量水合、响应膨胀等确定性指标，耗时门槛在稳定环境建立，避免把不同机器的单次波动判成回归。

### Android容量验证

`mobile/runtime.ts`在有效写入前后导出整库，`mobile/storage.ts`进行分块写入、临时文件校验和上一版轮转，原生环境通过二进制回读避免整文件的 Base64 桥接。附件也存于库中。容量改造需要保留失败回滚与写入完整性校验。

在隔离库中分别增加题目正文、PDF／图片和历史，以例如10／50／200MiB的实际库容量测量手机保存P50／P95、峰值内存、恢复、后台及进程回收。容量只是测试档位，不是承诺的最低设备支持上限。现有模拟器流程和布局结果继续保留。

若附件是主要成本，优先评估附件文件化和内容哈希去重；若整库持久化主导，再评估保持同等事务／恢复保证的增量存储适配。业务代码继续通过ORM／查询层访问数据。SQLite官方WASM持久化方案也有Worker与平台要求，需单独验证适配，见[官方持久化说明](https://sqlite.org/wasm/doc/tip/persistence.md)。

## 值得推进的功能扩展

### 统一导入查重与差异确认

按用户2026-11-06的决定，近期范围收敛为导入查重，不建设内容包版本／上游基线账本。普通内容导入自动复用完全重复题，相似候选展示差异，由用户选择覆盖、保留原题或保留两者；覆盖保留原ID与学习历史。使用增量轻量索引和有限候选，分批分析、确认后统一落盘。现有质量管理可继续用于历史重复题的人工核对。

时间预算、周目标和AI实际用量统计已完成并验收，操作见[使用说明书](./使用说明书.md)。供应商价格与Token口径不同，按用户要求只统计实际用量，不接入费用或预算。后续根据实际使用反馈调整估时与近似候选质量。

### PDF正文搜索与学习闭环

文字 PDF 已支持本地按页全文检索、命中页高亮、索引进度和断点续建，并可从原文回查关联题目。1.0候选包复验现有流程。扫描件使用外部 OCR，内置 OCR、公式识别和语义检索保留为候选方向。普通分享继续按内容包规则处理原文引用。

### 近似题与概念覆盖维护

导入批次现已支持完全重复复用、同批与既有题的近似候选、差异查看和逐项确认。后续可把平时维护发现的近似问题接入现有质量管理，不另造平行问题列表。

先使用题名、词头、概念别名和既有检索生成候选，显示题面、答案、来源和差异，必要时让AI补充判断。统一进入现有质量管理，不增加平行的问题列表。用户可保留、建立关系或处理重复；不自动合并题号、转移历史或删除题目，代码、化学式和否定词不作粗暴归一化。

### 判题标准质量与针对性补学

用户已决定不加入人工核定的AI评分样本集，本规划继续遵守。AI判题依据原题、本次作答和实际生效的判题标准，沿用题集覆盖与快照。判题标准在线质量扫描已完成，空标准、空来源、空独立解析的合法性继续与字段契约保持一致。

进一步可以用现有错题、相似题与专注复习形成“错误原因 → 一两道针对题 → 再次验证”，优先利用既有题目。高错误率作为排查线索，不能自动证明题目错误或学习者整个领域未掌握；全部审核通过也不等于逐题事实核验。

## 工程整理与条件性扩展

组题编辑、题目列表／详情／编辑以及中央OpenAPI映射仍有较多职责集中。沿后续改动逐步拆出状态控制、预览、保存和业务输出契约；中央接口文档聚合模块契约，减少通用object兜底。同步迁移所属样式并删除旧规则，保留冷开／返回／失败保存的回归。当前重点是明确边界和减少重复，不按文件行数机械拆分或一次性全仓重写。

| 方向 | 最小形态 | 开始条件 |
| --- | --- | --- |
| AI用量统计 | 本轮实现实际Token、调用覆盖、模型／任务分组 | 不加入价格或预算，口径与缺失值保持可核对 |
| 学习事件增量交换 | 手动导出／预览合并，按稳定事件ID去重并重放 | 需要电脑与手机交替学习时，先补设备身份、题目版本、重置标记和笔记冲突规则 |
| 音频与听写 | 先补已有英语／日语词卡的播放、听写与来源信息 | 明确音频来源、离线资产和导出规则 |
| 轻量知识关系 | 概念的先修、相关和易混淆关系，连接原文与题集 | 有实际学习路线需求后，优先普通关系表和既有标签 |
| OCR／拍照识题 | 提取后允许编辑和核对，再生成待审题 | 文字PDF检索与页段引用稳定后，单独验证表格和公式 |
| 编程实作 | 编辑代码、样例测试及清楚的执行结果 | 有实际练习需求后建设独立受限执行环境 |

AI实际用量以供应商返回为准，缺失时显示未知，不把输入字节冒充Token或固定金额。当前已兼容无`choices`的流式用量帧，失败／取消保留已返回用量，并标明不完整或未知。DeepSeek用量契约见[官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)，本轮不提供费用估算。

现有迁移合并会保留同ID本地记录与已存在卡片的事件链，不等于双向同步。增量交换需先解决事件身份、删除／重置和内容版本，再考虑自动上传下载；避免双向覆盖数据库文件。现有备份与完整恢复继续承担灾难恢复职责。
