# 认知星图后续扩展规划

更新日期：2026-11-10。1.0 是本地单用户学习工具的首次正式发布和功能定版，后续以缺陷修复、性能、可靠性和易用性维护为主。原 3.0 计划已并入 [1.0 发布清单](./1.0发布清单.md)，不再另列定版任务。本文保留有实际触发条件的方向，不自动转为开发待办。

## 当前判断

题库与资料、练习／考试、专注复习、FSRS、多领域计划、统计、搜索、内容质量维护、原文关联、AI 辅助和跨端文件迁移的基础闭环已经完成。首次使用引导、保数据更新、统一导入查重、时间预算、周目标、PDF 全文搜索、后台任务和 AI 用量统计均已进入验收记录，不再列为待开发功能。

最终候选全量测试为 1,418 通过、4 项缺可选内容文件跳过、0 失败。源码、实际发布包、模拟器和实体设备的覆盖范围分别记录，不能把已通过流程理解为任意设备、容量或全部题目事实均已核验。当前结果与条件项见[验收记录](./验收记录.md)及[发布清单](./1.0发布清单.md)。

继续沿用 TypeScript、React、Fastify、Kysely 和 SQLite 及现有平台适配边界。多人教学、协作、社区、题库市场和通用 AI 助手不属于当前产品范围。人工核定的 AI 评分样本集、AI 费用预算也不纳入计划；判题继续由原题、作答和实际生效的判题标准决定，用量按供应商实报记录。

## 维护优先级

| 顺序 | 方向 | 触发条件与验收方式 |
| --- | --- | --- |
| 优先修复 | 数据、判分和恢复正确性 | 复现丢记录、重复交卷、错误计分、恢复失败或安全边界问题时处理；用最小复现和相关回归确认 |
| 按反馈优化 | 日常交互和可访问性 | 根据具体的遮挡、焦点、保存失败或入口歧义改进；复测手机、键盘操作和返回上下文 |
| 持续测量 | 启动、查询和大批量任务 | 固定数据集与环境，区分冷启动、首次索引和预热；先检查全量水合、响应膨胀、重复查询及峰值内存，再决定实现改动 |
| 条件补验 | 实体 Android 与实际容量 | 分别增加题目、附件和历史，记录保存、恢复、内存、进后台及进程回收；模拟器结果不作为手机容量承诺 |
| 长期维护 | 恢复副本与临时空间 | 实际观察到副本累积或空间压力后，再补副本大小、日期、验证状态及清理预览；始终保护可用恢复副本和引用中的附件 |
| 持续质量 | AI 供应商与内容质量 | 供应商契约变化或用户反馈触发定向复验；保留失败原因、用量缺失状态及人工确认，质量问题进入现有质量管理 |

已有 [测试入口](./测试与验收.md)、[隔离与 CI](./测试隔离与CI.md)和[生成文件维护](./生成文件维护.md)继续复用。耗时门槛需在稳定环境建立，不把不同机器的单次差异判作回退。公开内容包独立维护来源、许可、审核状态与适用范围。

已复现的轻微维护项：Android 16 暗色主题下系统状态栏黑字对比偏低，滚动内容会进入状态栏区域。本轮主流程未被阻断，后续样式修复应在同一真机复测明暗主题和横竖屏，证据见[真机补测](./验收记录.md#2026-11-10-android-16-真机补测)。

Android 多次完整恢复会保留多份恢复前副本，界面目前只提供最近一份的导出入口。后续可补齐副本查看与清理，并保护最近的有效回滚点。实测占用见[性能与空间验收](./验收记录.md#2026-11-10-性能与空间验收)。

## 有条件的候选方向

以下内容只在日常使用确有需要时单独评估，不影响 1.0 的功能定版。

| 方向 | 最小范围 | 前置条件 |
| --- | --- | --- |
| 恢复副本账本 | 枚举恢复前副本，提供导出、验证与显式清理预览 | 保留最近有效副本，处理引用和失败恢复，不把旧副本只作为不可见文件累积 |
| 近似题与针对性补学 | 将已有候选对比、错题和专注复习串联到现有质量／学习流程 | 不另建平行问题列表，不自动合并题号、转移历史或按错误率认定题目有错 |
| 音频与听写 | 为已有词卡补播放或听写 | 明确音频来源、离线资源、许可和导出规则 |
| 轻量知识关系 | 连接概念的先修、相关与易混淆关系 | 有明确学习路线需求，优先复用标签、原文和题集 |
| 学习事件增量交换 | 手动导出、预览合并、稳定事件去重及重放 | 先明确设备身份、题目版本、删除／重置及笔记冲突，不直接双向覆盖数据库文件 |
| OCR 或拍照输入 | 提取后编辑核对，再生成待审题 | 单独验证表格、公式和扫描件；当前继续支持外部 OCR |
| 自动更新或存储改造 | 基于实测缺口提出独立方案 | 保留手动升级、备份和回滚；维持相同的事务及恢复保证 |

## 工程维护边界

按实际修改逐步整理复杂页面、状态控制和接口契约，复用已有模型、查询层、组件和样式。不按文件行数机械拆分，也不一次性重写全仓。涉及持久化时先识别正文、附件或整库保存的实际成本；容量方案保留失败回滚与完整性校验，业务层继续通过查询层访问数据。

每个后续维护项应写明具体问题、复现、影响范围和验证方法。修复后更新当前验收记录，旧测量和过程归入[历史索引](./history/README.md)。发布步骤、保数据更新和回滚统一按[发布与部署](./发布与部署.md)执行。
