# 认知星图开发与维护

目录职责与新增代码放置规则见[项目结构](./项目结构.md)。服务端根目录仅保留启动入口，业务规则、路由、跨端共享模型与前端功能均按模块维护；移动文件后应执行`npm test`、类型检查及两端构建，并同步检查发布入口和资源路径。

产品操作见[使用说明书](./使用说明书.md)，项目安装入口见[README](../README.md)。本文件说明代码边界、验证和发布维护约定。

统一验证入口为`npm run check`（范围格式、Server/Web/Android类型、文档），`npm test`运行全部隔离测试；两端构建分别为`npm run build`和`npm run mobile:build`。格式范围及测试缓存、浏览器和CI约束见[测试隔离与CI](./测试隔离与CI.md)。

## 运行环境

测试环境如需完整清空学习痕迹，先停止应用并完成编译，再在项目根目录运行`node scripts/maintenance/clear-learning-state.mjs`查看数量；显式加`--apply`才执行。工具先备份本地SQLite，再清除学习状态（含收藏和笔记）、作答及答题草稿、学习摘要、单题历史、复习卡／事件和AI辅助历史；题库、题集、资料、编辑草稿、附件及配置保持原样并核对哈希。这比产品中的“重置学习进度”范围更大，只用于明确需要清空的测试工作库。备份留在被Git忽略的`data/backups/`，不要用于发布。

- Web 服务与构建使用 Node.js 24.x，最低 24.13；依赖版本以 `package-lock.json` 为准。
- Windows 桌面端以 Electron 加载本机服务，交付物内置独立 Node.js 24 运行时和生产依赖；消费者无需安装开发环境。
- TypeScript、React、Vite、Fastify、Kysely 与 SQLite 构成主要实现；没有额外数据库服务。
- Android 使用 Capacitor、sql.js 和原生文件桥，共用业务规则，运行时无需 Node.js 或桌面服务。
- Android 构建使用 JDK 21、Android SDK API 36；SDK、Gradle 缓存与签名文件通过本机环境配置，不进入发布包。

```powershell
npm ci
npm run dev
```

开发页面默认 `http://127.0.0.1:5173`，服务接口 `http://127.0.0.1:4317/api`。生产页面由同一个 4317 端口提供。运行时生成的接口文档在 `/api/docs/`，OpenAPI JSON 在 `/api/openapi.json`。

## 必要检查

```powershell
npm run typecheck
npm run mobile:typecheck
npm test
npm run docs:check
npm run build
```

测试只能操作内存库、临时目录或明确命名的隔离数据库。不得在用户库中新增测试题、录入测试密钥、改保留策略或上传测试附件。浏览器验收使用 Playwright；未安装时可用 `PLAYWRIGHT_MODULE` 指向本机模块，脚本不得固化个人机器路径。

对 AI 的测试应区分：固定本机 provider 用于协议、超时、结构和版本冲突验证；真实模型测试需要使用者明确配置端点、模型和凭据，验证当前服务是否可用。模型某次输出正确不等于内容审核准确率或评分准确率保证。

教材真实验收可在完成Web构建后运行`node --import tsx scripts/qa/check-ai-live-textbook.ts`。它只读工作库的现有AI配置，所有业务写入均使用隔离内存库；模型只接收公开教材片段和合成回答。凭据不写日志、命令行或测试报告；教材PDF、生成结果及报告写入被忽略的`test-results/ai-live-textbook/`。支持使用`PLAYWRIGHT_MODULE`、`PLAYWRIGHT_CHANNEL`选择本机浏览器运行时，脚本有外部模型费用及联网需求，不属于默认离线测试。该固定教材样本验证提取、出题、待审确认、审核、解析、判题与推荐链路，不代表所有教材均可直接处理。

流式验收必须通过分块提供商与实际HTTP连接验证：模型尚未完成时已收到阶段／答案片段，最终结果前没有分析记录；结构错误、服务错误和中途断线不产生成功记录，断开或取消不能发布待审题。覆盖普通JSON状态码、SSE终端错误、考试锁、同源检查及原生进行中取消。相关用例见 `tests/ai/ai-stream-api.test.ts`；组题还需检查提示词独立限定范围和数量、手动条件交集、超过300题候选、大卷分批与跨批去重、500作答项上限及并发源版本变化。完整测试数量与本次实际执行范围记入[验收记录](./验收记录.md)。

真实 WASM 测试覆盖 SQLite提交、文件持久化、重启与失败回滚；手机权限、系统分享、前后台生命周期及机型差异仍需真机验收。

AI成功与失败记录使用判别联合，失败／取消无`result`且不能应用。provider仅发送安全阶段与数值诊断，不存原始错误正文；未知异常不回显消息。原生非2xx先回滚业务，仅允许服务端审计标记对应、通过严格schema校验且本次新建的失败记录重放，再整体持久化；保存失败仍507并回退。批任务和反馈AI复查返回逐项结果，部分失败用业务状态表达，已有成功项可正常落盘。

`ai_import_jobs`包含用户明确保存的提取正文，仅完整SQLite备份／恢复保留；列表和详情移除源全文，普通JSON和内容分享不携带。教材候选题的资产引用进入版本6派生投影，原始教材正文不作为应用资产引用解析。`question_feedback`随可信JSON与SQLite迁移，普通分享不带私人反馈；疑似摘要采用当前页批量查询，只读POST在原生白名单内。考试快照和作答接口不增加反馈或学习提示。

## 实现约定

1. 先定义 `shared` 协议与服务端硬校验，再提供页面。判题、组合题展开、分值精度和时限只能有一套业务规则。
2. 新增业务用独立注册模块，由应用入口装配；避免把页面状态、模型调用和数据库事务塞入同一个文件。
3. 分类、标签、题型、文件格式、书目类型和审核状态分别表达不同含义，不能互相代替。
4. 跨实体改动在事务内验证完整引用图。分类防环且父子同领域，领域标签必须匹配，图片与组合小题引用不能丢失。
5. 修改题目、题集或默认配置，不得重算已有作答快照、分值、考试期限和历史结果。
6. `null` 主观分表示未判定，`0` 表示已经评为零分；掌握度与真实得分分别记录。
7. 新题新增、可信备份迁移和分享导入分别走各自流程，不能用格式转换或AI建议绕过用户确认与硬校验。
8. 模型文本视为不可信资料。已有题号、题量、选题范围、分数上限、版本戳和引用仍由服务端校验。
9. AI建议只有在显式应用后才能变为评分、学习笔记或题集。模型不能自动读取工作目录或取得其他配置。
10. 桌面与移动端写请求均在持久化成功后返回成功；移动端保存失败必须恢复内存快照。修改数据库指针的副本操作须与运行库隔离。

## AI执行与组题维护

所有AI生成路由共用 `runAiAction`；普通JSON仍按原HTTP状态返回，显式请求SSE才建立事件流。流已建立后通过 `error` 事件报告失败，客户端须等待唯一完整的 `result`，不能把HTTP 200或答案片段视为成功。进度事件只描述已经开始或完成的实际工作，禁止模拟思考、回放缓冲结果伪装实时输出，或输出提供商隐藏推理、私有错误正文与密钥。

提供商请求接收同一个执行上下文和AbortSignal。每次异步模型返回后检查取消状态，保存分析记录及自动发布前再次检查，再执行版本、引用和分数硬校验。SSE写入只在HTTP适配层使用；Android不访问原生HTTP响应对象，通过进程内订阅发送阶段，仍完整等待路由与文件提交。当前原生网络适配未声明流式能力，因此请求完整JSON，不逐字播放完成后的答案。后续网络传输若声明支持流式，必须在Promise完成前调用真实分块回调，并保留取消、超时和字节上限。

AI组题输入的 `count` 可省略，显式范围1—500；自动时优先读取提示词数量，没有数量默认20。高级筛选形成硬约束，不能被模型扩大。轻量元数据查询、候选排序、摘要字节预算和按输出能力分批共同限制单次请求，不再对整个候选池设300题上限，也不使用全表完整JSON作为每批输入。批次之间保留已选题号和剩余作答项额度，完成后统一检查去重、来源版本和500个展开作答项上限；部分成功不能保存成完整推荐。可调整的候选范围仅限本次实际送入比较的题目；返回统计必须区分手动范围可用量、识别匹配量与实际比较量。

## 计时与草稿维护

作答草稿与组题编辑草稿是不同实体，分别配置保留数。继续草稿更新原ID；新建会按最近时间裁剪。进行中的考试不得被普通草稿保留策略删除。

普通练习用开始至提交的持续时间计算用时。考试保存服务器生成的开始时间、时长与绝对期限，刷新或后台不会暂停。期限之后收到的保存、提交请求不能替换既有答案；显式同步接口幂等完成交卷。服务端以API白名单限制其他功能，客户端通过全局守卫锁定功能导航，关页或离站使用浏览器提示，恢复时再次核对期限。

移动端只对成功的写请求落盘，因此期限同步使用 `POST /api/exams/sync` 或 `POST /api/attempts/:id/sync`。GET查询不能暗中修改数据库。

## 文件与密钥

题目展示与导出使用`shared/questions/content-notices.ts`解析明确的说明模板，原始记录仍保留完整来源。`web/shared/ui/content-notices.tsx`提供题目内容和整页去重折叠入口，普通Markdown不自动套用；`server/modules/transfer/exports.ts`在MD/PDF附录集中条款并保留适用题号。增加规则时必须基于明确模板及AST节点，不按“许可”“学习”等泛化关键词隐藏正文。回归为`tests/content/content-notices.test.ts`与`tests/practice/exports.test.ts`；真实词卡界面复跑`node scripts/qa/check-content-notices-ui.mjs`，依赖先构建Web及可选英语内容包。

上传资源保存在SQLite中，题目、资料、笔记、卷面和历史作答快照共用受控引用。Markdown不执行原始HTML，外部图片不会自动下载。PDF转换仅处理用户选择并预览的本地文本；扫描资料应先完成OCR。

AI密钥为只写配置。内容分享与JSON备份不包含AI私有配置；SQLite下载在独立副本移除密钥并清理旧页，原库保持原样。自行复制的原始数据库可能含密钥，应放在用户私有位置。

## 发布与维护

发布前通过全部检查，验证全新安装为零题目、零领域分类标签，只有基础默认配置，AI关闭且没有端点或密钥。发布脚本采用文件白名单并产生校验清单，源码包与运行包分别验证；内容通过`content:domains`单独按领域导出。

统一入口为 `npm run release`，源码根目录另有 CMD 的 `release.cmd`、PowerShell 的 `release.ps1` 与 Bash 的 `release.sh`。不传目标时交互选择，也可直接传入目标和选项；Linux 可用 `sh ./release.sh web`，或 `chmod +x ./release.sh` 后直接执行。三个入口要求 Node.js 24.13 或更新的 24.x 与 npm，首次构建时自动安装开发依赖；`clean` 不安装构建依赖。

在源码项目根目录用`--version`指定发布版本，例如`.\release.cmd web --version 1.5.1`、`.\release.ps1 all --version 1.5.1`或`sh ./release.sh web --version 1.5.1`。显式指定版本后不再询问；未指定时交互终端询问，回车保持当前值，非交互运行保持当前版本。正式执行同步package与lock版本，成功后持久保留在工作区；检查或构建失败时尽力回滚，遇到外部编辑则保留并提示核对。Android版本由构建自动映射，各目标包名使用所选版本；脚本不会自动commit、打标签或发布GitHub Release。`--dry-run`即使带版本也不写版本，`clean`不询问版本并拒绝`--version`。新增工具能力不自动更改当前1.5.0软件版本；版本格式、产物示例与升级要求见[选择发布版本](./发布与部署.md#选择发布版本)。

支持 `all`、`windows`、`web`、`android`、`docker`、`source`、`clean` 目标；`--dry-run` 查看计划，构建目标的 `--docker-command-only` 仅输出镜像构建命令。Linux / macOS 的 `all` 将 Windows 桌面目标标为待构建并提示使用 Windows 构建机；当前没有 Linux 桌面产物。未安装 Docker 时 Docker 目标记为待构建，已安装但构建失败则记为失败。Android 使用 Node 跨平台入口，Linux/macOS 无需 PowerShell。统一发布的 `all`、`android` 在测试与打包前预检正式签名、JDK 21 和 Android SDK API 36 / Build Tools 36.0.0；未通过就停止，正式 APK 不能退回 unsigned。独立 `npm run android:release` 是开发构建入口，无签名配置时允许生成 unsigned 包。命令、前置条件与各平台升级规则见[发布与部署](./发布与部署.md)。

正式交付物统一写入 `artifacts/releases/`，Android 使用 `noetic-atlas-版本-android.apk`，并附与文件摘要绑定的公开 `android-signing-report.json`。所有目标成功且未跳过测试时，自动核对附件并生成新的 `artifacts/github/v版本-UTC运行时间-pid/`；本次 `release-report.json` 的 `uploadDirectory` 指向该目录，通常无需重复运行 `release:prepare`。签名报告只包含公开验证信息，私钥和密码不得进入源码或交付物。

上传完成后，`npm run release -- clean --dry-run` 预览实际归档和清理范围；`npm run release -- clean` 将所有版本领域题库包校验归档到 `data/release-archives/domain-packs/` 后删除可重建的软件产物。CMD、PowerShell、Bash 及交互菜单同样支持 `clean`，原 `npm run release:clean` 继续可用。该目标只接受 `--dry-run`、`--help` / `-h`，不构建、不校验 Android 工具链或签名、不生成发布报告。归档内容冲突时停止，不覆盖已有数据；工作数据库、正式签名、工具链、依赖、Web/API 编译文件和测试报告继续保留。

源码包用于开发及各平台构建；Web 运行包需要安装生产依赖；Windows 桌面包将 Electron、独立 Node 运行时与生产依赖一起交付，不能误用 Electron 内置 Node 来运行需要 `node:sqlite` 的服务。

运行包应在独立解压目录执行冒烟测试，检查首次初始化、接口文档、练习提交、重启持久化及默认配置。Web 包可执行真实 `npm ci --omit=dev`，避免本机开发依赖掩盖缺失依赖。Windows 应从解压目录运行可执行文件，验证服务就绪后显示窗口、重复启动、端口隔离、关闭清理、可写数据路径与升级保留数据；测试不能访问开发者的工作数据库。

更新时停止服务、备份用户数据、替换程序并保留数据路径。正常启动不读取本地旧`seed.json`；显式测试种子注入与产品默认安装分开，升级不得自动重灌任何题库。签名和凭据由发布者私有保管，不能随源码或APK分发。

数据库采用JSON权威实体、轻量读取投影与事务校验。业务层不得导入 `node:sqlite` 或调用原生 prepare/exec；使用 Kysely 的链式查询和绑定参数。JSON函数、自然排序缓存、触发器、日志模式及备份等方言细节集中在数据库适配层；业务中不要拼接 SQL 字符串。新增列表先在数据库筛选分页，再解析当前页；不要先 `store.all` 全表读取快照后分页。

读取投影可通过 `database.projections.rebuild()` 从权威实体重建，不能作为修改题目或绕过审核的通道。它增加一些本地存储，换取避免每次列表查询都传递完整解析和快照。冷启动按版本与脏队列准备投影，正常访问只处理变化的记录。WASM 的 export/restore 会重开连接，适配器必须恢复自定义函数，排序 TEMP 缓存按需重建。复测方法见[查询性能与数据库访问](./查询性能与数据库访问.md)。

## 发布前目录维护

源码、当前说明、测试入口与许可证保留在对应模块；阶段核查与验收报告归档到`docs/history/`，正文和来源证据保留。`npm run docs:check`递归校验当前与归档文档的相对链接。

工作题库、内容暂存和数据归档在被忽略的`data/`。发布上传只使用`release-report.json`的`uploadDirectory`，旧上传目录、解压的Windows程序、`.localtools/release-staging`及重复APK均可在校验后清除；正式签名与SDK、Gradle等工具链继续保留。完整发布后需要删除所有软件产物时，使用`npm run release -- clean --dry-run`预览，再执行`npm run release -- clean`，该命令会先保护并归档数据包。

测试临时文件位于被忽略的`test-results/`，当前发布的日志与汇总保留，较早证据可压缩到`test-results/archive/`；归档可按原目录恢复。Vite/native编译缓存属于可重新生成的文件。运行中的服务构建和正在使用的桌面数据不能直接清理。
