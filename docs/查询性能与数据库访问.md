# 查询性能与数据库访问

后续启动、统一搜索、教材目录与筛选交互的合成压测和优化，见[2026-10-29性能核查](./性能核查-2026-10-29.md)。以下2026-10-23数据保留其原测量口径，两轮数据不直接混用。

## 结论与测量范围

2026-10-23 在本机使用同一份工作库的隔离副本及升级后的工作服务复测：30,150 道题、200 份归档词汇卷、196 个资源。原始题目 JSON 约 93.90 MiB，题集快照约 77.88 MiB。以下是本地 HTTP 请求直到响应体读取完成的中位数，改造前 3 次、改造后工作服务预热后 5 次；另列冷请求成本，不代表所有机器或 Android 真机性能。

| 接口场景 | 改造前 | 改造后 |
| --- | ---: | ---: |
| 初始化与统计 | 1,658 ms | 25 ms |
| 默认题库 30 条 | 4,657 ms | 29 ms |
| 化学领域筛选 | 1,104 ms | 176 ms |
| 全文搜索 transaction | 1,220 ms | 324 ms |
| 当前题集列表 | 691 ms | 12 ms |
| 包含归档卷的列表 | 646 ms | 12 ms |
| 精确英语词头查询 | 325 ms | 3 ms |

资源列表改造后约 8 ms；其第一轮仅批量预筛正文的实现仍约 1,397 ms，因此进一步改为精确引用索引。改造前完整实现没有在工作服务上执行资源列表压测，避免其逐资源扫描所有快照长期阻塞服务。上述差异来自查询方式、投影与前端请求组织，原项目没有 ORM 可归责。

默认题库第一次请求还会准备数字自然排序缓存，本次约 399 ms，后续为 31–44 ms。首次升级需要从原文生成派生投影，成本集中在初始化；新增或编辑题目后只处理脏记录。任意子串搜索仍扫描规范化搜索文本，领域与标签筛选仍需检查精简元数据；它们没有被描述为常量时间。更大规模若引入全文检索，须另行约定分词与子串语义，不能悄悄改变现有搜索结果。

## 原因与改动

原题库请求先读取、JSON.parse 全部正文，再逐题查询学习记录，最后在 JavaScript 中自然排序并分页。初始化为了计数也读完整题库和题集快照。资源页对每个资源重复扫描六类实体，资料页逐条重复加载分类。前端首屏还串行等待初始化与考试同步，旧集合筛选提前加载全部集合（该独立功能现已合并到题集），计时器更新会触发 Markdown 重复解析。

现在题目筛选、匹配计数与分页由一个查询完成，匹配 ID 供计数和选页复用；当前页关联正文和学习记录。首页用数据库聚合。题集列表读取计分所需摘要并继续验证计分快照，详情与作答仍使用原始冻结快照。资源引用按结构提取一次并索引，支持历史材料、笔记、嵌套 assetId、合法编码路径，排除二进制、远程 URL 及非法路径后缀。活动考试守卫只读 ID。

前端并行请求启动状态，保留考试锁校验；筛选集合按展开需求读取；通用 AI 状态复用初始化响应；取消过期请求；相同 Markdown 内容复用渲染结果。没有使用长时间响应缓存来掩盖查询成本，更新后无需等待 TTL。

## 查询层与数据库替换

采用 Kysely 0.29.7 的类型安全查询构建器，按其官方[构建与执行分离方式](https://kysely.dev/docs/recipes/splitting-query-building-and-execution)组织代码。

- `server/database/schema.ts` 定义表类型和记录表白名单；业务查询使用链式构建器。
- `connection.ts` 集中执行编译后的 SQL 和绑定参数，管理事务、初始化和备份；原生 SQLite 仅在该驱动边界使用。
- `sqlite-expressions.ts` 集中 JSON、数组、Unicode、日期与行顺序表达式；固定字段名校验后才能构造 JSON 路径。
- `projections.ts` 管理题目元数据、规范化搜索文本、精确词头、题集摘要、资源引用及版本化脏队列。
- `question-order.ts` 保留已有数字自然排序，使用只含 ID 的临时缓存；外部连接更新、回滚、WASM 重开连接均有验证。

JSON权威数据继续便于跨版本迁移；读取投影是可重建数据，不能代替原文。没有额外引入实体映射 ORM：当前无需对象关系自动加载，查询构建器足以消除业务 SQL 拼接，并避免再引入隐式 N+1。

现已验证 SQLite 与 sql.js/WASM 的真实执行。PostgreSQL/MySQL 只做了相同 CRUD/筛选查询的编译、占位符与参数化验证，没有声称实库运行。后续替换数据库需增加连接执行器、JSON/数组/排序方言、模式迁移与实库事务测试；当前同步仓储及事务回调还需要随网络数据库执行器调整为异步。这些改动限定在数据访问与调用边界，不能仅改连接 URL 就完成。

## 安全与验证约束

外部值均作为绑定参数；题型、分页、标签和引用继续经过 Zod 与业务校验，动态记录表有运行时白名单。架构测试禁止服务模块导入原生 SQLite 或通过 db.prepare/db.exec 绕过查询层。SQLite 特有的触发器与维护 SQL 仅存在于数据库适配目录，表名来自代码常量。

读取投影与脏标记随事务提交或回滚，不改变题目审核、笔记、时间戳、评分与 AI 凭据。数据库下载仍在副本清除密钥并清理旧页。原始个人库不进入公开种子或发布 ZIP。

回归覆盖所有题库筛选与旧 JavaScript 结果对照、Unicode/数字排序、注入与字面搜索、空页、当前页正文读取上限、组合题评分、考试守卫、索引重建、其他连接写入、嵌套事务、SQLite/WASM 持久化及失败回滚。浏览器另验证请求并行、重复请求、迟到响应隔离及 Markdown 更新行为。

题集学习进度使用 `/api/learning/*` 按来源查询。作答历史先取小型头部排序，再只读取当前页快照，响应不含题目与答案正文；错题评判通过方言适配器提取题型、答案规则和评分等必要字段，完整题目只用于当前页阅读。来源筛选复用既有 `(source,paperId,status)` 表达式索引；旧记录缺少 `source` 时使用可索引的空值分支，避免 `coalesce` 包裹索引字段导致全表扫描。实际路由回归核对执行计划、来源隔离与无关正文不读取。

固定汇总题集以紧凑判分字段合并来源，正文仅在分页选中后读取。普通卡片按当前页最多100份题集执行一次批量请求，后端固定批量读取作答元数据、题集成员和学习状态，不逐卡查询。题集成员优先采用干净读取投影；脏或缺失的投影只对相关记录回退原数据，不在这些读取接口中写缓存。SQLite与WASM同时验证纯读取和脏投影的新鲜性。

## 本地复测

```sh
npm test
npm run build
npm run mobile:build
node scripts/qa/profile-api.mjs --url http://127.0.0.1:4317 --runs 5 --assets
```

性能脚本只请求本机 GET 接口，输出每次耗时、中位数和响应字节，不输出题目、笔记或凭据。默认报告为 `test-results/performance/http-after.json`；使用 `--out` 可保留不同版本报告。建议复制同一数据库到隔离路径，通过 `DATABASE_PATH`、`PORT` 启动，分别测试初始化、首次请求与稳定访问，关闭会争抢 CPU 的构建或其他压测。测试与性能报告目录被 Git 忽略。
