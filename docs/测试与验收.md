# 测试与验收

单元及集成测试继续使用 `npm test`，默认最多4个文件工作进程，避免SQLite/WASM、编译和桌面进程验收相互争抢资源；可用 `npm test -- --test-concurrency=2` 显式调整。格式、类型和文档检查使用 `npm run check`。本页的统一运行器组织专项脚本，不代替单元测试，也不负责构建、安装浏览器或创建正式发布包。

## 统一入口

```sh
node scripts/qa/run.mjs --list
node scripts/qa/run.mjs --group smoke
node scripts/qa/run.mjs --only practice-timing-ui,practice-timing-strict-ui
node scripts/qa/run.mjs --group static --dry-run
```

不传参数默认运行六项隔离浏览器冒烟，与GitHub Actions的 `ui-smoke.yml` 使用同一份清单。`--group` 和 `--only` 可重复，也接受逗号分隔；选择结果合并、按清单顺序执行并去重。未知参数、组或检查项ID会报错，不会退回默认检查。

| 组 | 范围 | 前置条件 |
| --- | --- | --- |
| `smoke` | 长表单保存、资料筛选、阅读布局、配置保存、按领域导出、统一数据包 | Web构建、Playwright及浏览器 |
| `browser` | 现有浏览器专项与隔离模拟AI流程 | Web构建、Playwright；部分内容专项还需要可选公开内容包 |
| `static` | 文档链接、工程边界、两端静态加载依赖 | Web及移动端构建 |
| `performance` | 合成题库的启动、查询、题集、资料库、学习计划及大批量导入导出／迁移规模 | 不并发其他构建或全量测试；启动器检查需要Web构建 |
| `live-ai` | 已配置供应商的真实解析、判题、辅助编辑、教材导入、批处理、反馈及近似题 | 配置已启用，显式添加 `--allow-live-ai`；教材专项需要Web构建和浏览器 |
| `release` | 已生成的运行包和Windows便携程序验收 | 对应发布产物；Windows项仅在Windows执行 |
| `content-audit` | 既有内容维护操作与其备份的只读差异核对 | 相应操作记录、备份，显式添加 `--allow-operator-data` |
| `android` | 实际设备上的专用QA APK自适应检查 | 模拟器或设备、ADB、专用QA APK |

旧公开JSON内容包的内容事实专项会先检查可选输入，缺失时记录`skipped`和具体文件，既不启动检查子进程，也不冒称通过；`--list`可查看各项条件。普通功能测试继续使用合成夹具。

`--all` 只合并 `browser`、`static` 和 `performance`，不会隐式调用真实AI、读取工作数据库核对内容、运行发布产物或操作Android设备。即使写了允许开关，这些检查仍需要用组或单项ID显式选择。`--list` 和 `--dry-run` 只输出检查清单及命令，不启动任何检查，也不触发AI调用。

```sh
node scripts/qa/run.mjs --group live-ai --allow-live-ai
node scripts/qa/run.mjs --group android
```

真实AI检查读取当前配置并发送合成或公开资料，会产生供应商请求；不要把该组加入默认离线CI。内容核对只检查既有操作，不导入或发布题库。专用Android布局检查不应安装到正式应用包名，也不应清理正式应用数据。

## 大批量传输与AI组题专项

`node scripts/qa/run.mjs --only transfer-scale`默认建立37,400道合成题目的临时磁盘数据库，覆盖容量预检、按领域ZIP分片、默认查重首次与重复导入、关闭查重预览、200道修订题近似查询，以及包含完整答卷和单题历史的整体／领域SQLite迁移。报告位于`test-results/transfer-scale/report.json`，记录各阶段累计耗时、文件体积、比较次数、哈希复用和峰值内存。可用环境变量`TRANSFER_SCALE_COUNT`调整为100至50,000；计时应避免并发构建或其他大规模测试。脚本不打开工作数据库，临时数据库用完删除。

`node scripts/qa/run.mjs --only ai-paper-plan-live --allow-live-ai`使用已开启的供应商配置，只读抽样450道通用日语词汇，在内存库执行提示词识别200题、4批推荐、数量／元数据一致性与最终保存。最多6次供应商请求，记录安全调用参数与实际用量；不会将测试题集和用量写回工作库。确定性异常回归另覆盖错误单批标题、调整题量、重复ID、缺题、截断及过期候选，无需联网。

## 环境与结果

先执行 `npm run build`；涉及移动端加载图时再执行 `npm run mobile:build`。浏览器工具保持可选依赖，可通过 `PLAYWRIGHT_MODULE` 指定已有Playwright的入口文件。`PLAYWRIGHT_CHANNEL` 可选择 `msedge`、`chrome` 或 `chromium`，共享工具在Windows默认使用Edge，在Linux/macOS使用Playwright管理的Chromium。新专项应复用 `scripts/qa/helpers/browser-harness.mjs`，统一创建内存库、动态端口并拦截外部网络。

共享浏览器就绪等待默认为120秒，覆盖冷启动开发资源准备；`QA_FIXTURE_READY_TIMEOUT_MS` 可在1,000至300,000毫秒内调整。页面操作仍按专项的原有等待和断言执行，延长准备时间不能替代交互正确性检查。历史专项逐步迁移到共享工具，清单仍保留各专项独立运行入口。

运行器串行执行每一项，不会并发多个规模测量。日志和汇总写入 `test-results/qa-runs/<UTC时间-进程号>/`，每项有独立 `.log`，`report.json` 在每项结束后更新并保留：

- `passed`、`failed`、`timed_out`、`skipped`、`cancelled` 和未执行项。
- 每项持续时间、退出码以及日志相对路径。
- 整体是否完成，不把平台跳过当作已经验证。

单项失败后继续执行其余选择项，最后以非零退出码报告失败；超时终止本次拥有的检查进程树。Ctrl+C会停止本次检查并记录未执行项。运行器不会自动重试，模型失败或不稳定界面断言不能被后一次成功覆盖。各专项原有截图及细节报告仍保留在各自目录，统一报告负责定位它们对应的运行日志。

## Android原生布局验收

先启动模拟器或连接设备，使用 `adb devices` 确认序列号。构建需要JDK 21、Android SDK API 36 / Build Tools 36.0.0及Gradle工具链；`--offline` 适用于依赖已经缓存的环境。SDK不在项目默认的 `.localtools/android-sdk` 时，运行设备检查前设置 `ANDROID_HOME` 或以 `ANDROID_ADB` 指定ADB可执行文件。Playwright入口仍可由 `PLAYWRIGHT_MODULE` 指定。

```sh
npm run qa:android:build -- --java-root "C:/Path/to/jdk-21" --sdk-root "C:/Path/to/android-sdk" --offline --install --serial emulator-5554
npm run qa:android -- --serial emulator-5554 --exports
```

`--sdk-root` 可省略，改用已经配置的SDK路径。构建产物为 `test-results/android-layout/noetic-atlas-qa.apk`，固定包名为 `cn.noetic.atlas.qa`，使用独立测试入口及调试签名。构建脚本在 `finally` 中执行 `cap copy android`，恢复正式Android工程中的生产资源；QA入口和APK不进入正式发布目录。

每轮设备检查会先保存 `test-results/android-layout/device-before.json`，记录屏幕大小、密度、旋转、字体缩放和输入法设置；退出时恢复快照，另写入 `device-cleanup.json` 校验恢复结果。检查前后都会清空 `.qa` 应用的测试数据，不操作正式应用 `cn.noetic.atlas` 的数据。

布局检查以设备当前整体分辨率与密度为基线，再测试方向和字体缩放等状态。1080×1920、480dpi设备的实际WebView视口约为360×616 CSS像素，具体值以报告中的运行时测量为准。修改Android字体缩放后需要重启QA应用的WebView才能生效，检查脚本已经执行该步骤。

如果需要验证真实软键盘避让，可传入已经安装的专用本地测试输入法服务；例如：

```sh
npm run qa:android -- --serial emulator-5554 --exports --ime cn.noetic.atlas.qa.ime/.QaInputMethod
```

脚本临时切换该输入法并在结束后恢复原设置，不负责安装输入法。布局报告和截图位于 `test-results/android-layout/`。

通过统一运行器执行 `android` 组时，需要预先设置 `ANDROID_SERIAL`。运行器不向单项透传 `--serial` 或 `--ime`；需要这些参数时使用上面的独立命令。

```powershell
$env:ANDROID_SERIAL = 'emulator-5554'
npm run qa -- --group android
```

测试结束后，可卸载专用QA应用；正式应用继续保留：

```sh
adb -s emulator-5554 uninstall cn.noetic.atlas.qa
```

## 新增与维护专项

在 `scripts/qa/catalog.mjs` 中明确登记ID、脚本路径、组、环境要求及超时。真实AI或工作数据检查须声明对应访问类型，不能放入默认冒烟。新增脚本若未登记，`tests/infrastructure/qa-runner.test.ts` 会报错，避免脚本存在但无人知道如何运行。

`check-learning-reset-ui.mjs` 是维护专项的旧别名，统一运行器将其归并到 `maintenance-ui`，避免重复执行相同断言。`serve-*.ts` 是专项拥有的隔离服务夹具，辅助文件不单独登记成测试项。`audit-*.ts`、`profile-api.mjs` 等内容核查或显式本机测量工具继续独立使用，不会被自动加入离线运行。

`--exports` 使用同一专用APK实际导出PDF与Markdown，验证系统分享面板、PDF页数与中文文字；`--ime`另验证键盘弹出后的保存条。字体以gzip内容的`.ttf.bin`资源分发，专用构建会核对APK中的原始字节，避免Android打包工具自动处理`.gz`扩展名。
