# 生成文件维护

构建资源由同一份清单准备，日常使用 `npm run generated:prepare`、`generated:check` 和 `generated:clean`。这些命令在源码项目根目录运行，需要先执行 `npm ci`。发布包清理与题库归档仍使用[发布清理入口](./发布与部署.md#发布产物清理与题库归档)。

## 文件归属

| 位置 | 维护方式 |
| --- | --- |
| `web/assets/fonts/` | 保留原始中文字体、OFL许可和来源说明，作为生成输入提交Git。 |
| `public/licenses/` | 保留9份受控许可证快照；生成时与当前依赖及字体许可核对，变更通过Git审查。未知文件必须先人工核查，工具拒绝直接删除。 |
| `public/fonts/` | 可重建的网页导出字体，由原始字体确定性压缩生成，忽略Git。 |
| `public/pdfjs/` | 可重建的完整PDF.js字符映射和标准字体，忽略Git。 |
| `mobile/assets/` | 可重建的离线资源，包含干净基础配置、SQLite WASM、字体、PDF.js资源和许可证，忽略Git。 |
| `dist/server/`、`dist/shared/`、`dist/web/`、`dist/mobile/` | 编译输出，由对应构建命令生成，忽略Git。 |
| `android/app/capacitor.build.gradle`、`android/capacitor.settings.gradle` | 保留受控的原生项目连接配置，随插件变更核对，不按临时文件删除。 |
| Android原生源码、图标、Gradle Wrapper | 保留源码和必要构建基础文件。 |

字体使用 `.ttf.bin` 文件名保存gzip字节。Android的AAPT会自动解压并改名 `.gz` 资源，因此不能仅把后缀改回 `.gz`。运行时按协议解压完整字体；不裁剪中文字符来缩小包体。

PDF.js的 `cmaps/` 和 `standard_fonts/` 支持旧教材、不同编码及离线文本提取，应完整保留。某个测试样本没有用到，不代表可以删除。这些兼容资源、许可证与原始字体和重复构建副本有不同用途。

## 准备与校验

```sh
npm run generated:prepare
npm run generated:check
```

两者默认目标为 `all`。只处理某一平台时使用：

```sh
npm run generated:prepare -- --target web
npm run generated:check -- --target web
npm run generated:prepare -- --target mobile
npm run generated:check -- --target mobile
```

`prepare` 先读取并校验所选目标的全部输入，再预检所有输出目录。输入缺失、基础配置不干净，或者发现目录联接、私密文件等异常时，准备停止，尚未清理已有输出。对于变化的派生目录，清除旧文件后按清单重建；对于完全相同的内容，不重写文件，不改变修改时间。资源目录不写入当前时间等波动信息，重复准备不会仅因为资源生成时间而使启动缓存失效。

`check` 只读比较文件名与内容，报告缺失、变化和多余项；不自动修复。目录内有上一版残留文件或多余空目录也会报告。依赖升级后先准备，再检查并审查许可证差异。

新克隆的仓库尚无派生二进制资源，可以先执行：

```sh
npm run generated:check -- --source-only
```

该模式只核对9份许可证快照及Git中的派生目录边界，不要求预先生成字体、PDF.js副本或移动资源；仍需安装锁定依赖。完整资源验收应在准备后运行默认检查。Git边界检查只采用项目自身的独立仓库；源码包尚未建立独立仓库时会说明检查不可用，避免误用外层个人文件仓库。

现有 `prepare-third-party.mjs`、`prepare-mobile.mjs` 和 `clean-build.mjs` 继续作为内部稳定入口，调用统一资源规则与路径保护。网页的开发和构建会准备所需资源；移动构建在同一轮准备中生成完整离线资源，再交给Vite，不重复复制第三方资源。

## 清理与重建

先停止使用相应 `dist` 输出的服务或桌面实例，再清理构建目录。同一工作区的资源准备、构建、原生同步和清理应串行执行。`generated:clean` 默认为预览，只有显式 `--apply` 才执行：

```sh
npm run generated:clean
npm run generated:clean -- --scope assets --apply
```

| 范围 | 固定目录 | 重建方式 |
| --- | --- | --- |
| `assets`（默认） | `public/fonts/`、`public/pdfjs/`、`mobile/assets/` | `npm run generated:prepare` |
| `build` | `dist/server/`、`dist/shared/`、`dist/web/`、`dist/mobile/` | 网页与服务端运行 `npm run build`；移动端运行 `npm run mobile:build` |
| `all` | 上述两组目录 | 分别执行资源准备及需要的平台构建 |

例如：

```sh
npm run generated:clean -- --scope build
npm run generated:clean -- --scope build --apply
npm run build
```

这是可重建文件的永久清理，不设回收站，也不备份旧字体、旧JS等产物。工具只接受上述固定范围，不接受任意清理路径；执行前检查所有目标及内部目录，拒绝符号链接、Windows目录联接、数据库、归档、签名或私密配置，防止前一目录已删除后才发现后一目录存在异常。发现已提交Git的派生文件时同样拒绝清理，应先确认归属。

以下内容不属于该入口：受控许可证快照、原始字体、原生项目源码、工作数据库、题库包归档、个人配置、正式签名、`.localtools/` 工具链与缓存、`test-results/` 验收证据，以及 `artifacts/` 发布交付物。发布交付物使用独立 `release clean` 流程；不要把整个 `test-results/` 或 `.localtools/` 当成普通构建输出删除。

## 源码包与运行包

源码ZIP保留原始字体、许可、原生项目及构建脚本，排除 `public/fonts/`、`public/pdfjs/`、`mobile/assets/` 的派生副本。安装依赖后通过准备或平台构建恢复；运行包则必须包含当前构建使用的 `.bin` 字体、离线PDF资源及许可证。

增加生成资源时，在 `scripts/build/generated-assets.mjs` 声明来源、所属目录与预期内容；新增清理目录时同时检查 `generated.mjs` 固定范围、`generated-paths.mjs` 路径边界、Git忽略、源码／运行包收集和对应测试。不要分别在网页、Android和发布脚本中维护多套复制清单。
