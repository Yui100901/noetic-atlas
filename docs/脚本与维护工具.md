# 脚本与维护工具

`scripts/`按用途组织开发工具。日常操作从根目录启动脚本或`package.json`中的命令进入，构建、发布和测试入口会调用对应的辅助文件。

## 常用入口

| 操作 | 命令 | 使用范围 |
| --- | --- | --- |
| 启动本机学习站 | `启动学习站.cmd` | 检查成功构建，必要时安装依赖或重新构建，再启动指定数据路径 |
| 只查看启动计划 | `启动学习站.cmd --plan` | 检查构建状态，输出计划 |
| 开发调试 | `npm run dev` | 启动API与Vite开发服务 |
| 格式、类型与文档检查 | `npm run check` | 检查受控格式范围、三端类型、许可快照、生成目录Git边界和文档链接 |
| 全量自动化测试 | `npm test` | 自动发现`tests/`下的测试文件 |
| Web与Android资源构建 | `npm run build`、`npm run mobile:build` | 生成`dist/`及离线资源 |
| 资源准备与一致性校验 | `npm run generated:prepare`、`npm run generated:check` | 共用Web／Android资源清单，核对旧文件、缺失项和内容变化 |
| 预览清理可重建文件 | `npm run generated:clean` | 默认预览，仅`--apply`执行，固定资源／构建范围 |
| 软件发布 | `release.cmd`、`release.ps1`、`release.sh` | 共用`scripts/release.mjs`选择目标、版本、检查和打包 |
| 按领域导出题库 | `npm run content:domains` | 读取工作库的一致性副本，另行生成领域ZIP |
| 预览清理发布产物 | `npm run release -- clean --dry-run` | 列出归档与清理范围，确认范围后再运行`clean` |

运行环境、开发命令见[开发与维护](./开发与维护.md)，生成文件的保留／清理边界见[生成文件维护](./生成文件维护.md)，发布目标及签名要求见[发布与部署](./发布与部署.md)。

## 目录职责

| 目录 | 文件类型与职责 |
| --- | --- |
| `scripts/`顶层 | 开发、启动、测试、格式和发布的统一入口 |
| `build/` | 第三方资源、移动资源、Android工具链与签名、成功构建缓存 |
| `release/` | 源码／Web／Windows包、版本同步、附件摘要、APK资源核验和发布清理 |
| `testing/` | 隔离自动化测试共用的原生运行时代码缓存 |
| `qa/` | 页面交互、布局、性能、交付物与专项验收；`transfer-scale`测大批量传输，`ai-paper-plan-live`显式测真实供应商200题分批推荐 |
| `maintenance/` | 显式学习数据重置及已有默认配置调整 |
| `content/` | 领域内容来源、生成目录、格式整理、导入导出和质量维护 |

`start.ps1`处理PowerShell环境定位和参数转发，启动判断及依赖准备集中在`start.mjs`。三个release外壳同样委托统一Node实现。更改流程时修改共用实现，保留命令行入口。

## 验收脚本的使用范围

| 名称或分组 | 用途与输入 |
| --- | --- |
| `check-*-ui.mjs` | 运行对应页面的浏览器断言。多数使用临时内存库，有些同时启动`serve-*.ts`构造场景 |
| `qa/helpers/` | 共用隔离浏览器进程、外网拦截和Vite准备流程 |
| `check-layout-ui.mjs --full` | 多页面、四种宽度、空库与主题巡检 |
| `check-*-scale.ts`、`search-scale-baseline.ts` | 合成数据的查询与加载测量，以及固定的历史性能对照实现 |
| `check-generated.mjs` | 只读核对受控许可和Git派生目录，不要求先生成二进制资源；归入`qa --group static` |
| `check-release.mjs`、`check-windows.mjs` | 解压／启动实际交付物，检查空库、数据持久化和进程释放 |
| `live-ai.ts`、`*-live.ts` | 显式真实模型验收，需要相应凭据和网络 |
| `profile-api.mjs` | 对指定本机服务采集只读请求耗时，默认地址为4317 |
| `audit-*.ts`、`check-*-applied.ts`等内容专项 | 读取内容源、历史操作报告或备份，核对特定批次的修改范围 |

浏览器验收需要先构建页面，并配置可用的Playwright。页面脚本统一推荐使用`node --import tsx scripts/qa/<脚本名>.mjs`，以支持直接导入TypeScript模块的验收。具体命令和隔离要求见[测试隔离与CI](./测试隔离与CI.md)。

`qa/`包含不同输入和运行环境的工具，不能把整个目录中的文件都当作普通测试自动执行。例行回归使用`npm test`和选定的页面验收，真实模型、实际服务画像与历史内容核对按各自输入运行。

## 内容源与维护批次

`content/`既有长期使用的管理命令，也有用于复现题库的领域目录和带日期的批次。日期说明内容来源与变更批次，保留生成目录、来源许可和校验工具，才能复现或核查现有题目。

| 工具 | 对应操作 |
| --- | --- |
| `manage.ts` | `content:validate`检查内容源，`content:package`生成独立分享包，`content:import`备份后导入工作库 |
| `export-domains.ts` | `content:domains`从现有通用已发布题生成可直接导入的领域包 |
| `review.ts` | `content:review`生成整理计划，显式`--apply`整理及审核，`--sync-sources`同步来源文件 |
| `audit-bank.ts` | 对指定库执行只读格式／结构规则检查并写报告 |
| `scan-quality.ts` | 创建并执行持久化质量扫描，会写入扫描和问题记录 |
| `backfill-rubrics.ts`、`vocabulary/standardize.ts` | 先预演，再按明确范围备份、校验和应用判题要求／词卡规范化 |
| `apply-*.ts` | 执行相应历史内容批次，使用前核对输入、计划和应用参数 |

普通题目编辑、审核和质量问题处理优先使用应用页面。工作库维护命令按任务范围显式运行，运行前核对目标数据库和备份。来源生成方法见[题库内容与来源](./题库内容与来源.md)，数据包转换与完整恢复见[数据包格式](./数据包格式.md)。

## 文件保留与清理

- `dist/`、`artifacts/`、`test-results/`和工具链缓存用途不同，不共用整目录清理。`generated:clean`只处理固定编译／资源目录；`release clean`另行处理发布交付物与内容归档；验收证据和工具链保留。
- `test-results/cache/`是可重建测试代码缓存。运行中的测试可能持有缓存锁，清理前先确认相关任务已经结束。
- `data/`保存工作数据、内容源及备份，`.localtools/signing/`保存正式签名。删除测试日志或发布中转时，清理范围应避开这些目录。
- 删除旧测试fixture前检查调用方和CI。历史说明使用`docs/history/`保留，长期稳定命令的薄转发入口可以保留供旧操作记录使用。

代码边界和文件放置规则见[项目结构](./项目结构.md)。
