# 项目结构与模块边界

本说明用于判断新代码应该放在哪里，以及移动文件时需要同步哪些入口。功能操作见[使用说明书](./使用说明书.md)，构建、运行与维护见[开发与维护](./开发与维护.md)，各平台交付见[发布与部署](./发布与部署.md)。

## 目录总览

```text
noetic-atlas/
├─ server/              服务端入口、业务模块、HTTP与数据库适配
│  ├─ core/             存储门面、校验、分页与读取模型
│  ├─ http/             请求处理、安全策略与OpenAPI
│  ├─ database/         查询执行、驱动、方言与读取投影
│  └─ modules/          按业务划分的服务与路由
├─ shared/              网页、服务端与移动端共用的模型和规则
├─ web/
│  ├─ app/              React启动、页面路由、工作台外壳与全局样式
│  ├─ shared/           前端共用组件、请求、媒体与导出
│  ├─ features/         按学习功能组织的页面与交互
│  └─ assets/           字体等受版本管理的静态资源
├─ mobile/              Android平台桥接、本地运行时与WASM适配
├─ desktop/             Windows桌面窗口、服务启动与进程管理
├─ scripts/             开发与发布入口，以及分组后的维护工具
├─ tests/               按职责分组的自动化测试
├─ config/              仅defaults.json作为公开基础配置；其余本机配置忽略
├─ data/                本地题库、数据库、备份与来源，整目录忽略
├─ public/              网页静态资源，含构建准备的PDF.js资源
├─ docs/                使用、设计、来源与维护说明
├─ dist/                编译产物
└─ artifacts/           发布包和可选题库交付物
```

`data/`整个目录、`dist/`、`artifacts/`、`test-results/`、`.localtools/`均被忽略。新源码不放入生成目录；工作数据和个人配置不进代码仓库或软件包。`scripts/content/export-domains.ts`在一致性副本上读取现有通用已发布题，导出多个自包含领域包，来源许可随内容包保留。

## 服务端

`server/main.ts` 启动服务；`server/index.ts` 创建应用、注册基础设施和业务路由。新增功能应进入对应模块，入口文件负责装配。

| 位置 | 职责与新增代码归属 |
| --- | --- |
| `server/core/` | `store.ts` 提供存储门面；`validation.ts` 放共用输入校验；`pagination.ts` 处理分页约定；`read-models.ts` 提供列表和统计读取模型。 |
| `server/http/` | 请求参数辅助、安全和同源限制、错误与接口文档等 HTTP 基础能力。 |
| `server/database/` | Kysely 查询执行、数据库连接、SQLite 方言和驱动适配，以及用于列表查询的投影与索引。 |
| `server/modules/ai/` | 模型请求与流式传输、执行上下文、组题检索与推荐、AI 输入校验及路由。 |
| `server/modules/questions/` | 题目查询、组合题结构、词头引用、学习元数据整理及题目路由。 |
| `server/modules/practice/` | 题集、作答会话、考试时序、计分、组题草稿及相应路由。 |
| `server/modules/assets/`、`library/` | 文件资源和学习资料的管理与校验。 |
| `server/modules/banks/` | 旧集合转题集的兼容迁移及新题导入，不提供独立集合管理接口。 |
| `server/modules/settings/`、`taxonomy/`、`study/` | 系统配置、领域分类标签、学习状态与复习记录。 |
| `server/modules/sharing/` | 面向他人的内容分享、依赖补齐、导入预览及冲突处理。 |
| `server/modules/transfer/` | 可信备份迁移、MD/PDF 导出所需的文档模型、许可附录及相关路由。 |

模块内存在 `routes.ts` 时，HTTP 解析和响应放在该文件；业务规则放在明确命名的服务或规则文件中。规模较小的模块可保持少量文件，新增职责独立后再拆分。

业务模块通过存储门面和统一查询层访问数据，使用参数化查询。SQLite 原生接口与方言细节集中在数据库适配层，业务代码不可直接调用。涉及完整导入、分享落库、评分与审核的修改，应明确事务边界。分页、统计与范围筛选优先由查询层完成，避免先读取全部题目正文再在内存中分页。替换数据库的适配与验证要求见[查询性能与数据库访问](./查询性能与数据库访问.md)。

## 跨平台共享代码

根目录的 `shared/` 是各运行端共用的代码，`web/shared/` 是前端内部共用代码，两者用途不同。

| 位置 | 内容 |
| --- | --- |
| `shared/models/` | 题目、领域、标签、资料、设置、分享和导出等数据契约。 |
| `shared/ai/` | AI 数据契约、传输约定、进度事件与 SSE 解析。 |
| `shared/questions/` | 题型和知识标签规则、学习记录整理、题目展示说明提取等纯函数。 |
| `shared/practice/` | 作答计时与状态、组题草稿等可复用规则和契约。 |
| `shared/assets/` | 附件标识、引用解析及生成文件的通用规则。 |
| `shared/utils/` | 跨运行端复用的基础工具，例如分页契约。 |

`shared/` 不依赖 `server/`、`web/`、`mobile/` 或 `desktop/`，不包含页面组件、平台存储访问或服务端路由。需要浏览器、设备或模型服务能力时，由调用方通过明确的接口注入。只有一个前端页面使用的表单状态放在所属功能目录，不上提为跨平台规则。

## 前端

`web/app/main.tsx` 是 HTML 入口加载的 React 模块，负责应用启动、导航、路由和全局状态装配。页面通过具体文件直接导入。

| 位置 | 职责与主要文件 |
| --- | --- |
| `web/app/` | `main.tsx`、全局 `styles.css` 与 `navigation.css`。 |
| `web/shared/lib/` | `api.ts`、分页、筛选整理、计分展示辅助，以及网页平台实现 `platform.ts`。 |
| `web/shared/ui/` | 通用控件、Markdown、标签选择与题目说明折叠；共用编辑和分类审核样式。 |
| `web/shared/media/` | 附件请求、上传、图片与 PDF 媒体展示。 |
| `web/shared/export/` | 导出选项、下载与 PDF 渲染。 |
| `web/features/questions/` | 题目列表、详情、编辑、批量导入、审核、组合题与词卡引用。 |
| `web/features/papers/` | 题集列表、详情、就地快照看题与前后题导航、手动与随机组题、分值和组题草稿；`paper-learning.tsx` 装配题集学习页签与已删除题集的历史入口。 |
| `web/features/practice/` | 作答页、随机单题、考试导航保护及共用的题集上下文学习面板；不再保留全局学习记录页面。 |
| `web/features/ai/` | AI 工作台、配置表单、推荐组题、评分与审核工具、流式进度和客户端传输。 |
| `web/features/library/` | 学习资料列表、详情、上传与编辑。 |
| `web/features/settings/` | 系统配置和数据备份迁移界面。 |
| `web/features/taxonomy/`、`sharing/` | 领域分类标签管理、分享与导入界面。 |

前端通过 HTTP 请求封装及平台接口使用业务能力，不直接导入 `server/`。Android 的同进程业务复用由 `mobile/` 运行时在平台边界内承接。跨页面共享的控件可以放入 `web/shared/`；只有某个功能使用的组件、样式和 hook 留在对应 `features/` 中。

`@platform` 是明确的平台替换入口：网页构建指向 `web/shared/lib/platform.ts`，Android 构建通过 `mobile/vite-aliases.ts` 指向 `mobile/platform.ts`。修改此入口应同时核对 TypeScript `paths`、网页 Vite 配置、移动 Vite 配置和使用源码的 QA。不要用宽泛的文件名匹配替换其他模块。

`web/assets/fonts/` 保持原位，字体文件、许可与来源说明一起维护。PDF 导出的动态字体引用、移动端许可复制脚本和打包检查依赖这个位置。PDF.js 的 worker、字库与字符映射资源有各自的构建准备流程，移动前先检查资源 URL。

当前样式包含全局选择器；同名样式文件应随所属模块移动，并保持明确的导入顺序。修改目录时不顺带重写选择器，以便将路径问题和样式变化分别验证。

## 脚本、测试与稳定入口

| 位置 | 用途 |
| --- | --- |
| `scripts/dev.mjs`、`release.mjs`、`start.ps1` | 开发、发布与启动入口。 |
| `scripts/build/` | 资源准备、移动构建、工具链准备、构建清理等工具。 |
| `scripts/release/` | Web、Windows 等发布包制作、公开数据和 APK 验证。 |
| `scripts/content/manage.ts`、`review.ts` | 内容管理和审核入口。 |
| `scripts/content/english/`、`japanese/`、`chinese/`、`driving/` | 各语言及驾驶内容生成器和领域数据。 |
| `scripts/content/computer/`、`chemistry/`、`medicine/`、`terminology/` | 计算机、化学、医学和术语内容生成器。 |
| `scripts/qa/` | 浏览器、交付物和场景验收；使用隔离数据，报告写入 `test-results/`。 |
| `tests/ai/`、`content/`、`database/`、`practice/` | AI、内容处理、查询与存储、练习规则测试。 |
| `tests/server/`、`mobile/`、`release/`、`architecture/` | 服务集成、移动适配、发布流程和模块边界检查。 |
| `tests/fixtures/` | 测试夹具，保持固定位置以便多组测试复用。 |

日常使用优先调用 `package.json` 中的 `npm run` 命令。根目录的 `release.cmd`、`release.ps1`、`release.sh`、`启动学习站.cmd`，以及 `index.html`、Vite 配置、`server/main.ts` 是需要一起维护的稳定入口。源码目录分组不改变对外 API 路径、页面 hash 路由或 `dist/server`、`dist/shared`、`dist/web` 等交付目录的职责。

服务端和跨平台共享 TypeScript 按 NodeNext 规则，在相对模块导入中使用对应输出的 `.js` 后缀；前端 TS/TSX 按 Vite/Bundler 规则引用具体模块，资源查询后缀如 `?url` 必须保留。新增文件与测试应核对对应 `tsconfig`、测试发现规则和打包入口，不能只依靠编辑器跳转证明构建可用。

同一模块内直接导入所需文件，不为每个目录建立汇总式 `index.ts`。跨模块复用通过明确的服务、数据契约或共用组件，避免从页面模块转导出另一功能的入口。新增依赖时检查循环引用，尤其不要让基础组件通过汇总导出反向加载页面或平台运行时。

## 新功能放置示例

- 新增题型：先在 `shared/models/` 与 `shared/questions/` 定义契约和纯规则，再修改服务端题目校验、练习计分与对应前端组件；测试分别进入内容、练习和服务集成组。
- 新增 AI 操作：契约与进度约定放在 `shared/ai/`，模型调用和保存逻辑放在 `server/modules/ai/`，交互放在 `web/features/ai/`；复用现有取消、预览、校验与明确应用流程。
- 新增数据库能力：在统一数据库层提供实现，业务模块通过已有门面调用，并补查询和事务测试。
- 新增可选内容：生成器放入对应领域目录，公开来源和许可写入 `data/content-sources/`，生成内容写入既定内容输出目录；保留新增审核流程。
- 新增学习页面：放入对应前端功能目录，由 `web/app/main.tsx` 的路由直接装配；只有确认存在多处复用时再提取共用组件。
