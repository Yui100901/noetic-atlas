### 现有词卡的读音与反向提示

英语、日语各10,000张原卡已补`vocabulary`结构；不复制题号，不改变原释义或原审核状态。20,000张均有独立释义提示并通过字面防泄题校验；词汇题集开始时选择顺向或逆向，逆向按本次选题生成引用原题ID的临时填空卷，原卡继续保留简答形式。详见[单词练习说明](./使用说明书.md#扩展内容包)。

- 英语每卡至少一组IPA，区分有来源的英式／美式读音。主源固定为ipa-dict提交`972cd67dd5f96bc5660e28070cde26e3928abcd7`；英式源ipacards适用GPL-3.0，美式源cmudict-ipa适用MIT，不能一概称为MIT数据。双源缺项27词中10词补开放词典记录，17词明确标注单位、罗马数字或拼写变体的展开/替代读法；未把另一方言复制成缺失方言。
- 日语10,000卡保留10,350组假名读音及对应规则罗马音。转写参考ALA-LC赫本式规则，保留多读音；自动转写不表示源词典提供了罗马音，也不表示音高或音频已核验。
- 原表、词典补充记录、完整许可、署名、可编辑重建脚本和逐词报告位于包内`sources/vocabulary/`。需整体保留；词卡阅读页折叠显示来源，避免把许可重复塞入题干。

重建方法见[词卡补充脚本说明](../scripts/content/vocabulary/README.md)。维护脚本`apply-expansion.ts`默认只预检；显式`--apply`前建立并验证SQLite备份，只补词卡结构与来源字段，并在事务内核对学习记录、配置、资料和历史卷面未变。维护报告保存在本地`test-results/`，不混入公开来源包。

Pillow可在独立Python环境用 `python -m pip install Pillow` 安装。Node项目依赖用 `npm ci` 安装；重建内容本身不会修改正在使用的数据库。

汽车原稿是RAR内的旧 `.doc`，Python解析器需要先转换成 `.docx`。在项目根目录按以下步骤操作：

1. 运行 `python scripts/content/driving/driving-car-official.py --download` 下载、校验RAR，并用7-Zip解出原DOC。首次缺少DOCX时只提示转换，不继续生成题目。
2. Windows已安装Microsoft Word时，运行 `powershell -NoProfile -File ./scripts/content/driving/convert-driving-document.ps1`。脚本校验原DOC哈希，隐藏窗口、禁用宏和外部链接更新，以只读方式打开，另存DOCX至缓存；不会覆盖原DOC，已有目标DOCX时拒绝覆盖。Linux或其他环境可使用自己的转换工具，例如LibreOffice，在隔离配置中关闭宏和外部链接后另存DOCX，并核对文字、图片和裁剪。
3. 再运行 `python scripts/content/driving/driving-car-official.py`；若DOCX保存在其他位置，传 `--docx <路径>`。转换软件会影响XML结构，换用工具或版本后应重新核对题数、选项、答案与图片绑定，不能仅凭文件可打开认定提取正确。

RAR与原DOC按来源清单固定哈希；提取文本哈希另记于清单。DOCX是本地转换产物，不把每次转换生成的ZIP字节差异视作官方源版本变化。原始下载与转换缓存均不随源码提交。

生成后统一验证、打包或选择导入：

```sh
npm run content:validate
npm run content:package
npm run content:package -- --packs chinese,computer-expansion
npm run content:import -- --packs english,japanese
npm run content:import -- --packs driving --database ./data/another-existing.sqlite
```

`--packs`名称使用上方规模表中的包名，支持逗号分隔；不填则处理全部包。导入工具仅接受已存在的工作库，先初始化目标应用；导入前自动备份到 `data/backups/`。相同ID且内容相同会复用，不覆盖本地编辑与审核状态；不同内容冲突时停止，需改用分享导入预览后重映射。

`content:package` 生成 `artifacts/releases/noetic-atlas-1.0.0-content.zip`，以及 `artifacts/content/` 下各领域的最多500题分包、词表Markdown、来源、许可、清单和SHA256。每个分享分包自含领域、分类祖先、标签、来源和所需本地图片。词汇关系跨分包时保留可读词名，避免留下指向未导入词条的坏链接。

内部内容JSON与分享JSON用途不同：前者用于构建验证，后者使用系统 `learning-share` 格式。大库或带附件的整库JSON可能超过80MiB接口上限，采用分包分享；完整工作状态迁移使用SQLite备份。分享包和内容ZIP不携带私人笔记、作答、草稿或AI密钥。

更换上游版本时，先核对许可和内容变化，再更新来源修订/哈希、重建、验证并重新审核受影响题目。哈希证明获取字节一致，不证明释义和答案正确；已审核旧内容不应在语义变化后自动沿用审核结论。

验证、导入与打包自动应用 `shared/questions/knowledge-tags.ts` 中的公共标签策略。需要将归一化结果写回构建源JSON并同步已有工作库标签时，使用 `npm run content:review -- --apply --sync-sources`，默认不改变审核状态。`--approve-all` 是另一个明确的全库发布选项，不会由导入命令隐式执行。详细命令、备份与范围见[整理记录](./题库整理记录.md)。清单中的 `catalogNormalization` 区分生成器原输出哈希与标签归一化后的输出哈希，避免把整理误称为上游源版本变化。
